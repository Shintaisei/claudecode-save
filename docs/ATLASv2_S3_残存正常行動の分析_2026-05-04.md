# ATLAS v2 S3 残存正常行動の分析

更新日: 2026-05-04

## 1. 問い

抽出が終わったあとに確認したいのは、  
「異常の起点だけが残っていて、研究で使える正常行動が消えていないか」である。

今回の分析では、high-confidence seed の中に

- どれくらい正常イベントが残っているか
- どの process 帯に正常文脈が厚く残っているか
- それが研究用の normal behavior seed として使えそうか

を見た。

参照:
- [normal_behavior_analysis_s3/results.json](/c:/Users/komat/OneDrive/Desktop/ATLAS以外のデータセット/analysis_data/model_runs/normal_behavior_analysis_s3/results.json:1)

## 2. 先に結論

研究で使えそうな正常行動は、十分残っている。

high-confidence seed 全体は `6 window / 3,000 event` だが、その内訳は

- attack: `195`
- normal: `2,805`

であり、normal 比率は `93.5%` である。

さらに normal 比率 `95%` 以上の window だけを `normal-dominant seed` として見ると、

- `5 window / 2,300 event`
- attack: `40`
- normal: `2,260`
- normal 比率: `98.3%`

となる。

つまり、「攻撃近傍なのに大半は正常イベント」という研究にちょうどよい帯が、かなりまとまって残っている。

## 3. どの帯が normal-dominant か

normal-dominant seed は次の 5 本である。

- `payload.exe`, `chunk 331-340`, `1000 event`, `attack 34`, `normal 966`, `normal_ratio 96.6%`
- `powershell.exe`, `chunk 271-274`, `400 event`, `attack 3`, `normal 397`, `normal_ratio 99.2%`
- `powershell.exe`, `chunk 295-298`, `400 event`, `attack 1`, `normal 399`, `normal_ratio 99.8%`
- `regsvr32.exe`, `chunk 181-183`, `300 event`, `attack 1`, `normal 299`, `normal_ratio 99.7%`
- `regsvr32.exe`, `chunk 251-252`, `200 event`, `attack 1`, `normal 199`, `normal_ratio 99.5%`

逆に、もっとも攻撃密度が高いのは

- `payload.exe`, `chunk 323-329`, `700 event`, `attack 155`, `normal 545`, `normal_ratio 77.9%`

である。

したがって、今回の抽出結果は

- 攻撃密度が高い seed
- 正常文脈が厚い seed

を分けて扱える状態になっている。

## 4. process ごとの見え方

dominant process ごとの集約は次の通りである。

- `payload.exe`: `1700 event`, `attack 189`, `normal 1511`, `normal_ratio 88.9%`
- `powershell.exe`: `800 event`, `attack 4`, `normal 796`, `normal_ratio 99.5%`
- `regsvr32.exe`: `500 event`, `attack 2`, `normal 498`, `normal_ratio 99.6%`

この結果から、研究用途としては次の読み方がしやすい。

- `payload.exe`
  攻撃そのものに最も近い帯
- `powershell.exe`
  攻撃前後の通常ファイルアクセス文脈が厚い帯
- `regsvr32.exe`
  攻撃連鎖の近傍で、ほぼ正常イベントからなる帯

特に `powershell.exe` と `regsvr32.exe` は、attack-near normal context の seed としてかなり扱いやすい。

## 5. 正常イベントの中身

normal イベントの多くは、`Security` の file access 系イベントで構成されている。

よく出ている EventID は主に次である。

- `4656`
- `4658`
- `4663`

つまり、今回残っている正常文脈は「攻撃の派手な実行痕」だけではなく、

- file object への通常アクセス
- その前後の process activity
- 複数 process が混ざる近傍文脈

を含んでいる。

例えば、

- `payload.exe` 帯では `payload.exe` に加えて `csrss.exe`
- `powershell.exe` 帯では `csrss.exe` や `vmtoolsd.exe`
- `regsvr32.exe` 帯では `repmgr.exe`, `eqnedt32.exe`, `taskhost.exe`

のような周辺 process も見えている。

このため、「攻撃点だけ」ではなく「攻撃近傍で普通に動いていたもの」も拾えている。

## 6. 研究でどう使えるか

今回残った正常行動は、少なくとも次の用途には十分使えそうである。

- 攻撃近傍の正常 file access パターンを読む
- 偽陽性を生みやすい正常コマンド列を集める
- `payload / powershell / regsvr32` 前後の通常動作を比較する
- attack-near normal context から正常行動 seed を再抽出する

特に、「純粋 benign ログ」ではなく「攻撃のすぐそばにある正常行動」を見たい研究にはかなり合っている。

## 7. 注意点

ただし、次の制約は明示しておいた方がよい。

- 今回の normal seed は主に `aalsahee|20220719T1430Z` 側に集中している
- 小さい真陽性 sequence 側の正常文脈は、まだ十分に残せていない
- ここでいう正常行動は `pure benign` ではなく `attack-near normal context` である

したがって、論文や報告書では  
「攻撃近傍の正常行動を残した seed」  
として書くのが一番誤解が少ない。

## 8. 全体判断

抽出後に残っている正常行動は、

- 量としては十分ある
- process 帯ごとに分けて扱える
- 異常 seed と正常寄り seed を分離できる

という意味で、研究材料としてかなり使いやすい。

へ進んでよい。
