# ATLAS v2 S3 異常検知モデル比較メモ

更新日: 2026-05-04

## 1. 今回の目的

ATLAS v2 の benign-only 学習で、S3 attack day を対象に「偽陽性研究の土台として最低限説得力のある detector」を見つける。

評価は、まず benign だけで学習し、その後 attack day 側 session に対して sequence 単位で正常/異常を判定する方針で揃えた。

## 2. 先に結論

現時点の最良条件は次である。

- モデル: `IsolationForest`
- 入力表現: session を `1-2 gram TF-IDF` に変換
- session 設計: `computer_user + 10分`
- contamination: `0.10`

この条件では、benign validation 由来の threshold をそのまま使っても

- `F1 = 0.667`
- `Recall = 0.667`
- `Precision = 0.667`

まで出た。

結果ファイル:

- [iforest_s3_cu10_g1_2_c010/results.json](/c:/Users/komat/OneDrive/Desktop/ATLAS以外のデータセット/analysis_data/model_runs/iforest_s3_cu10_g1_2_c010/results.json:1)

これは、これまで試した forecasting 系や AE 系より明確に良い。

## 4. 解釈

今回の S3 では、sequence を「次ログ予測で外したかどうか」で見るより、

- session 全体を 1 つの document とみなし
- template n-gram の分布ずれで benign からの距離を測る

方がうまくいった。

これは、ATLAS v2 の attack day では「局所的な次イベント予測ミス」よりも、「ある user 文脈における template 出現分布のズレ」の方が異常性を表しやすいことを示唆している。

## 5. 次の一手

次にやるべきことは次の通り。

1. `iforest_s3_cu10_g1_2_c010` を基準線として固定する
2. 同条件を `S4/M4/M5/M6` に横展開する
3. false positive になった session を中身で見て、どの benign drift が誤検知を起こしているかを調べる
4. 必要なら `LocalOutlierFactor` や `OneClassSVM` を同じ TF-IDF 表現で追加比較する

現時点では、偽陽性研究の出発点として最も現実的なのは `IsolationForest + cu10 + 1-2 gram` である。
