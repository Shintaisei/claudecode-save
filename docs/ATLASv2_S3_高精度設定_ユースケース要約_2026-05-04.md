# ATLAS v2 S3 高精度設定 ユースケース要約

更新日: 2026-05-04

## 1. 前提

ここでは、現時点で最も実務向きだった高精度寄り設定

- モデル: `IsolationForest`
- 特徴量: `session の 1-2 gram TF-IDF`
- session 設計: `computer_user + 10分`
- benign-only 学習
- threshold: benign validation の `p95`

を前提に、S3 で「異常 sequence を起点にどれくらい正常行動を拾えそうか」を整理する。

結果ファイル:

- [iforest_s3_cu10_g1_2_c010_stable/results.json](/c:/Users/komat/OneDrive/Desktop/ATLAS以外のデータセット/analysis_data/model_runs/iforest_s3_cu10_g1_2_c010_stable/results.json:1)

## 2. sequence 単位の成績

test 側の sequence は合計 `18` 本で、そのうち真の異常 sequence は `3` 本だった。

この設定では、

- 予測異常 sequence: `3` 本
- そのうち真陽性: `2` 本
- そのうち偽陽性: `1` 本

となった。

つまり sequence 単位では

- `Precision = 0.667`
- `Recall = 0.667`
- `F1 = 0.667`

まで出ている。

## 3. 何行くらいの sequence が異常になるか

test 全体のイベント数は `244,443` 行で、そのうち攻撃ラベル付きイベントは `292` 行だった。

この設定で異常 sequence として上がるのは 3 本で、合計イベント数は `118,495` 行だった。

内訳は次の通り。

- 予測異常 sequence 全体: `118,495` 行
- その中の攻撃イベント: `286` 行
- その中の正常イベント: `118,209` 行

割合で言うと、予測異常 sequence の中身は

- 攻撃イベント: 約 `0.24%`
- 正常イベント: 約 `99.76%`

である。

これは「異常 sequence を起点にしても、中身の大部分は正常ログである」ことを意味する。

## 4. 偽陽性の個別ログはどれくらいあるか

今回の予測異常 3 本のうち、1 本は偽陽性 sequence だった。

その偽陽性 sequence は

- [win-32-h1|win-32-h1$|20220719T1420Z](/c:/Users/komat/OneDrive/Desktop/ATLAS以外のデータセット/analysis_data/model_runs/iforest_s3_cu10_g1_2_c010_stable/results.json:1)
  これは結果 JSON には ID までは入っていないため、集計時に対応付けた
- 総イベント数: `23,680`
- 攻撃イベント: `0`
- 正常イベント: `23,680`

だった。

つまり、「偽陽性として人が見に行く完全正常ログ」は約 `2.4万行` 規模で混ざる。

## 5. 真陽性 sequence の中からどれくらい正常行動を抽出できそうか

真陽性として拾えた 2 本は次の通り。

1. `win-32-h1|aalsahee|20220719T1430Z`
   総イベント数 `76,194`
   攻撃イベント `281`
   正常イベント `75,913`

2. `win-32-h1|win-32-h1$|20220719T1430Z`
   総イベント数 `18,621`
   攻撃イベント `5`
   正常イベント `18,616`

合計すると、真陽性 sequence 2 本の中には

- 総イベント数: `94,815`
- 攻撃イベント: `286`
- 正常イベント: `94,529`

が入っている。

ここから言えるのは、

- attack を含む sequence を 2 本拾えた
- その中には約 `9.45万行` の正常イベントが含まれている

ということである。

したがって今回のユースケースでは、「異常そのものを pinpoint する」よりも、「異常を含む user 文脈を起点に、大量の正常行動文脈を回収する」用途に向いている。

## 6. 見逃しているもの

真の異常 sequence は 3 本あるが、そのうち 1 本は見逃している。

- `win-32-h1|-|20220719T1430Z`
- 総イベント数: `2,621`
- 攻撃イベント: `6`
- 正常イベント: `2,615`

この sequence は小さく、`aalsahee` や `win-32-h1$` の大きな異常 sequence に比べて分布ずれが弱かったと考えられる。

## 7. ユースケースとしての解釈

今回の高精度設定は、「SOC が attack day の中から investigation 起点を少数に絞り、その中で正常行動を掘る」用途にはかなり合っている。

理由は次の通り。

1. 18 本の sequence のうち 3 本だけを見ればよい
2. その 3 本のうち 2 本は本当に異常を含む
3. 真陽性 2 本の中だけでも約 `9.45万行` の正常文脈を回収できる

一方で、偽陽性 1 本だけで約 `2.37万行` あるため、「そのまま全部読む」にはまだ重い。

したがって実務上は、

- first pass: 今回の `IsolationForest + cu10`
- second pass: 予測異常 sequence 内をさらに chunk 化して再順位付け

の二段構えにするのが自然である。
