## 1. これは何か

- `CLOUSEAU` 実験に入る前に、追跡のイメージを具体化するための **試作版の答えデータ**
- まだ最終 gold ではなく、**現在の候補順位と生ログ観察から作った v0**
- 目的は
  - 起点から何を追うのか
  - どこまで取れたら正解とみなすのか
  - `正常 / 攻撃 / 判定不能` をどう置くのか
  を先に固定すること

答えデータ本体は [ground_truth_trial_v0_2026-05-10.csv](/c:/Users/komat/OneDrive/Desktop/ATLAS以外のデータセット/docs_active/ground_truth_trial_v0_2026-05-10.csv:1) に置いてある。

## 2. 読み方

各行は 1 ケースで、最低限次を持つ。

- `poi_process`
  - `CLOUSEAU` に渡す起点
- `expected_traceability`
  - `追跡可能 / 半追跡可能 / 追跡困難`
- `expected_outcome`
  - `正常 / 判定不能`
- `expected_related_processes`
  - 追跡の中で見えてほしい主要プロセス
- `expected_related_artifacts`
  - 追跡対象にしたい file / browser / service artifact の種類
- `success_condition`
  - 何ができたらそのケースを成功とみなすか

## 4. 追跡のイメージ

### 4.1 `explorer.exe`

- 起点
  - 単発の file access
- 何を追うか
  - 同じ局所時間帯の file access
  - 近い micro-chunk の document/file 操作
- 何が出れば成功か
  - `explorer.exe` 中心のファイル操作文脈が見える
  - 攻撃に無理につなげず benign に閉じられる

### 4.2 `winword.exe`

- 起点
  - 文書閲覧 / 文書オープン
- 何を追うか
  - 周辺 file access
  - 前後の document context
- 何が出れば成功か
  - 文書閲覧の benign context を復元できる

### 4.3 `repmgr.exe`

- 起点
  - 文書関連アクセスの一部
- 何を追うか
  - 周辺の file access
  - 近傍の `winword.exe`
- 何が出れば成功か
  - 文書アクセス連鎖としてつながる
  - ただし結論は `判定不能` でもよい

### 4.4 `firefox.exe`

- 起点
  - browser activity
- 何を追うか
  - browser 周辺 process
  - cache/download 系 artifact
- 何が出れば成功か
  - browser 中心の文脈は見える
  - しかし十分な artifact がなく `判定不能` でも自然

### 4.5 `repwmiutils.exe`

- 起点
  - 補助的 / 管理的な背景寄り処理
- 何を追うか
  - 周辺の support process
  - office-support chain
- 何が出れば成功か
  - 攻撃と誤判定せず、背景寄りの曖昧な連鎖として扱える

### 4.6 `spoolsv.exe`, `tpautoconnsvc.exe`

- 起点
  - 背景サービス
- 何を追うか
  - 同じ micro-chunk の service/process 混在
- 何が出れば成功か
  - 「情報が足りず追跡困難」と出せる
  - 無理に attack narrative を作らない

## 5. この v0 の使い方

- まずはこの 7 ケースを `CLOUSEAU` に流す
- 出力と `success_condition` を見比べる
- ずれたら ground truth を修正する

つまり、これは

- 最初から完全な正解
ではなく
- **最初の評価軸を固定するための叩き台**

として使うのがよい。

## 6. 客観性のために次に足すもの

この v0 を次の段階で強くするには、

- `expected_related_files` をもう少し具体化する
- 実際に前後 micro-chunk を読んで time window を確定する
- `正常` に置くケースと `判定不能` に置くケースの境界理由を書く

の 3 つが効く。
