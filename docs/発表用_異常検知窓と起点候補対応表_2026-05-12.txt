UC04   firefox.exe は browser 正常行動の代表例だが、今回入力では URL や artifact が不足
       browser は「存在は見えるが深掘りは弱い」ケース

       正常な監査手続として起点化しやすい

UC06   spoolsv.exe は強い偽陽性だが、背景サービスのため探索起点としては弱い

UC07   tpautoconnsvc.exe も同様に、強く上がるが意味の狭い起点にはしにくい

全体結論
- Security ログだけの異常検知結果からでも「どの時間帯に何系統の行動が異常化したか」は示せる
- ただし探索起点として強いのは process 名そのものではなく、後段で結び直せる
  command line / target filename / registry key を持つケース
- 今回の発表では次の整理が自然

  1. Security 異常検知で引っかかった窓
  2. その時間帯の正常行動解釈
  3. raw log に降ろしたときの起点候補
  4. 探索成立性の評価

- 実験として回しやすい入口
  - DropboxUpdate.exe -> C:\Windows\Temp\GUR*.exe
  - install_choco_software.ps1
  - logs.zip
  - net.exe accounts
  - SecEdit.exe /export /cfg C:\Windows\Temp\secexport.cfg
  - OneDrive.exe /background
  - HKU\...\Run\Discord
  - HKLM\...\Run\Dropbox

- 実験として回しにくい入口
  - explorer.exe 単独
  - firefox.exe 単独
  - spoolsv.exe 単独
  - tpautoconnsvc.exe 単独
  - svchost.exe 単独
