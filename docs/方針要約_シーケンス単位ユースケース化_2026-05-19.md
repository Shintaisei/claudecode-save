# 方針要約: シーケンス単位ユースケース化

更新日: 2026-05-19

## 1. 結論

- ユースケース作成の入力単位は、個別ログではなく **異常検知で上位化した高スコア sequence** に置く
- `100件` の上位候補から単発ログを拾うのではなく、**高スコア sequence をそのまま観察対象として使い、その内部から正常ユースケース候補を選ぶ**
- `micro-chunk` は最終入力ではなく、**sequence 内で何が異常スコアを押し上げたかを説明する補助根拠** として扱う

## 2. なぜこの方針にするか

従来の整理では、

- 検知器は sequence 単位で結果を返している
- しかし後段では個別ログを入力想定にしていた

という粒度のずれがあった。

このずれを残したままだと、

- 異常スコアが高くなった理由を周辺文脈込みで説明しにくい
- 実務では人手を減らしたいのに、後段で細かいログ拾い直しが必要になる

ため、**sequence をそのまま観察入力にする方が自然** である。

## 3. 新しい論理展開

1. 実務では、なるべく人手介入を減らして調査対象を絞りたい
2. 現状の異常検知は、sequence 単位で異常候補を出力できている
3. したがって後段も、その sequence を入力単位として受け取る方が自然である
4. その内部を読んで、正常だが偽陽性化しやすい行動をユースケース候補として選ぶ

## 4. この方針で言えること

- 異常検知の出力粒度と、ユースケース化の粒度が一致する
- 「なぜその候補を見るのか」に対して、`高スコア sequence だから` と一貫して答えられる
- 個別ログを後付けで拾ったのではなく、**異常検知結果から自然に得られた候補** だと説明できる
- 実務的にも、機械が sequence を絞り、人がその中を読むという流れに近い

## 5. 文書上の扱い

- 主根拠は `sequence rank`
- `micro rank` は sequence 内の局所根拠として補助的に使う
- `normal-only micro-chunk をそのままユースケースとみなす` という書き方は避ける
- `高スコア sequence の内部から抽出した正常候補` という表現にそろえる

## 6. 発表でそのまま使える短い言い方

「本研究では、異常検知で上位化した sequence をそのまま観察対象として扱う。その内部に含まれる正常寄りの行動をユースケース候補として整理することで、検知出力の粒度と後段の分析粒度を一致させ、実務的にも自然な偽陽性分析フローを構成する。」
