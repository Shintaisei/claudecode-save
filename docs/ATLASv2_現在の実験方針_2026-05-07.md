# ATLASv2 現在の実験方針
更新日: 2026-05-07

## 1. 方向性

### 1.1 研究背景

- サイバーセキュリティのエンドポイント監視に着目する
- エンドポイントでのインシデント対応の中でも、構造的に負担が集中し属人化が進んでいるインシデント分析に着目する

### 1.2 先行研究

- インシデント分析の自動化は、マルチエージェントシステムの登場により一気通貫の自動化が進んでいる
- しかし、攻撃を前提とした解析が一般的であり、実務で多い偽陽性の解析は未整理である

### 1.3 研究目的

- 実務で運用可能な水準でインシデント分析を自動化する
- 異常検知後のログを対象として、真陽性 / 偽陽性の双方に対する
  - 関連ログの調達
  - 攻撃 / 正常 / 決めきれないの判断
  を自動化する

### 1.4 マイルストーン

1. 正常な行動でも、起点から関連ログの調達が成立し、行動を再構成できるかを検証する
2. 攻撃 / 正常 / 決めきれない、の判断ができるかを検証する

### 1.5 現在地点

- 1. の「実際に再構成するユースケース」を作成している段階

## 2. ユースケース作成の流れ

1. 正常行動を含んだデータセットを用意する
   - 正常行動を4日間含むオープンソースデータセットとして `ATLAS / ATLAS v2` を選定した
2. 実務で使われるような異常検知モデルにかける
3. 本来は正常だが攻撃と誤判定されたログを抽出する
4. 抽出したログを、行動の複雑性を基準に整理する
5. それぞれの行動に対して、追跡のきっかけとなる起点ログを追跡難易度で選定する
6. 4 と 5 を掛け合わせて、9マスのテーブルを作る

## 3. 進捗

### 3.1 個別ログ検知モデルの結果

使用モデルは `Hayabusa` である。  
Hayabusa は網屋の主力製品であり、`Sigma` ルールに基づく個別ログ検知モデルとして位置づけられる。

今回の結果から、次の問題が明確になった。

- ファイルアクセス系のルールがなく、攻撃をほとんど拾えなかった
- 偽陽性として抽出されたログも攻撃の最序盤関連が多く、正常な行動の抽出にはつながらなかった

したがって、**今回の目的である「攻撃近傍の正常行動を回収すること」にはつながらなかった**。  
このため、単一ログで攻撃 / 正常を判定する方式から、**前後文脈を扱えるシーケンス単位で攻撃 / 正常を判定する方式**へ移行した。

| Scenario | 全イベント数 | 攻撃イベント数 | non-info alerts | TP | FP | TP / 攻撃イベント | FP / 全イベント | 読み |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| `S3` | 257,887 | 292 | 11 | 6 | 5 | 2.1% | 0.0019% | 数は少なく、TP と FP が混在 |
| `S4` | 231,335 | 478 | 14 | 7 | 7 | 1.5% | 0.0030% | 数は少なく、TP と FP が同数 |
| `M4` | 200,015 | 339 | 9 | 7 | 2 | 2.1% | 0.0010% | TP は出るが件数自体が少ない |
| `M5` | 315,508 | 313 | 18 | 5 | 13 | 1.6% | 0.0041% | FP が多いが clean な正常 seed ではない |
| `M6` | 220,858 | 297 | 10 | 5 | 5 | 1.7% | 0.0023% | 数は少なく、TP と FP が混在 |

### 3.2 シーケンス検知へ移行した理由

- 単一イベントではなく、ログ集合を見て検知する
- 個別ログ検知と比較して、前後文脈を考慮した解析ができる

一方で、シーケンス単位の検知は本質的には有効だが、次の弱点がある。

- 何を根拠に怪しいのか説明しにくい
- 人や端末の些細な行動変化に惑わされやすい
- チューニングが重い

そのため、実務では個別ログ検知モデルの補助として使われることが多い。

### 3.3 先に結論

2026-05-07 時点の結論は次の2点である。

1. **first pass は成立した**
   - `ユーザ単位・10分ごと + 1-2gram TF-IDF + IsolationForest`
   - benign-only + `p95` 閾値でも `F1=0.667, Recall=0.667, Precision=0.667`
2. **second pass も、手作業ヒューリスティックなしで比較可能な形まで整理できた**
   - `100 event chunk + 1-2gram TF-IDF` に統一し、`IsolationForest / OneClassSVM / LOF / kNN / SGDOneClassSVM / SVD再構成誤差` を比較した
   - `LOF` は `top1 chunk` で attack に到達し、`OneClassSVM` は `top10 chunk` で `30 attack event` を保持した
   - `SVD` は `first attack rank = 2` で一定の局所化を示したが、`top10` 時点の attack 保持は弱かった
   - ただし、モデルごとの挙動差は大きく、second pass の最終採用はまだ確定していない

以下では、この結論に至った根拠を順に示す。

### 3.4 first pass の公平比較の考え方

これまでの探索では、`forecasting / reconstruction / one-class` の代表的手法を試行した。  
ただし、deep 系は「時系列そのもの」、one-class 系は `TF-IDF` というように入力表現が揃っておらず、厳密には「モデル比較」ではなく「構成比較」になっていた。

そのため、2026-05-07 時点では、まず **first pass を公平な条件に近づけること** を優先し、次の2段階で再実験した。

1. **モデル比較**
   - 系列の切り方を `プロセス単位・10分ごと` と `ユーザ単位・10分ごと` に限定
   - 入力表現を `1-2gram TF-IDF` に固定
   - 判定器を `IsolationForest / OneClassSVM / LOF` に固定
2. **入力表現比較**
   - 上で最も有望だった `IsolationForest` を固定
   - 前処理は最小限にとどめ、`1-1gram / 1-2gram / 1-3gram TF-IDF`、`1-2gram count`、`1-2gram binary`、`1-2gram tf` を比較

閾値はすべて、**正常検証データから決めた `p95` 閾値**で統一した。  
したがって、以下の結果は `oracle best` ではなく、**benign-only 運用を想定した統一条件比較**である。

なお、one-class 系の判定器はログ系列をそのまま入力できないため、各系列をテンプレート列としてトークン化し、固定長ベクトルに変換して入力する。  
今回の `TF-IDF / count / binary / tf` は、いずれも **同じ系列をどのような数値ベクトルに写像するか** の違いである。

### 3.5 first pass の最終採用構成

first pass の最終採用構成は次である。

- 系列の作り方: `ユーザ単位・10分ごと`
- 入力表現: `1-2gram TF-IDF`
- 判定器: `IsolationForest`
- 閾値: benign validation 由来の `p95`

この構成は、

- 系列数を `18 -> 3` に絞れる
- `TP 2 / FP 1` まで落とせる
- 攻撃近傍の正常文脈を多く残せる

という意味で、今回の目的に最も合っている。

### 3.6 採用構成の根拠 1: シーケンスの切り方

`ATLAS / ATLAS v2` は、4日間の正常データと、5日目に攻撃が行われる構成になっている。  
今回の実験では、4日間を学習に使い、最後の1日に対してシーケンス単位の攻撃 / 正常予測を行った。

今回は比較条件を揃えるため、`10分` を固定し、単位だけを変えて比較した。

| 系列の作り方 | 全イベント数 | 生成された test シーケンス数 | attack を含むシーケンス数 | 1系列の意味 |
| --- | ---: | ---: | ---: | --- |
| プロセス単位・10分ごと | 257,887 | 109 | 8 | 1つのプロセス単体の流れ |
| **ユーザ単位・10分ごと** | **257,887** | **18** | **3** | **1人のユーザの行動文脈** |

### 3.7 採用構成の根拠 2: one-class 系でベクトル化が必要な理由

`IsolationForest / OneClassSVM / LOF` のような one-class 系の判定器は、ログ系列をそのまま入力できない。  
そのため、各系列をテンプレート列としてトークン化し、固定長ベクトルに変換してから入力する必要がある。

今回比較した `TF-IDF / tf / count / binary` は、いずれも **同じログ系列をどのような数値ベクトルに写像するか** の違いである。

### 3.9 モデル比較の読み

- 同じ `1-2gram TF-IDF` で揃えると、`ユーザ単位・10分ごと + IsolationForest` が最も安定した
- `プロセス単位・10分ごと` は、`OneClassSVM` では拾いすぎ、`IsolationForest / LOF` では厳しすぎる結果になった
- `ユーザ単位・10分ごと` は、シーケンス数を `18 -> 3` に絞りつつ `TP 2 / FP 1` を維持できた

したがって、**first pass のベースライン構成は `ユーザ単位・10分ごと + 1-2gram TF-IDF + IsolationForest` とする**。

### 3.11 入力表現比較の読み

- `1-1gram` は coarse すぎて、ユーザ単位では偽陽性が増えた
- `1-3gram` は細かすぎて、攻撃系列を取りこぼしやすくなった
- `count` と `binary` は重み付けが弱く、ユーザ単位では偽陽性が増え、プロセス単位では攻撃系列を拾えなかった
- `tf` は今回の条件では `tfidf` とほぼ同じ結果になった
- `1-2gram TF-IDF` が、攻撃保持と絞り込みのバランスが最も良かった

### 3.12 採用構成の根拠 5: deep 系の棄却

探索段階で一度試していた `LSTM / Transformer / AutoEncoder` についても、  
「系列定義まで含めて本当に棄却してよいか」を確認するため、次の条件で再評価した。

- 系列の作り方: `プロセス単位・10分ごと` と `ユーザ単位・10分ごと`
- 学習: 4日間の benign-only
- 判定対象: `S3 attack day`
- 閾値: benign validation 由来の `p95`
- `LSTM / Transformer`: `top10 miss ratio`
- `AutoEncoder`: `max reconstruction score`

| モデル | 系列の作り方 | 異常スコア | F1 | Recall | Precision | 予測陽性 | 読み |
| --- | --- | --- | ---: | ---: | ---: | ---: | --- |
| `LSTM` | プロセス単位・10分ごと | `top10 miss ratio @ p95` | 0.000 | 0.000 | 0.000 | 0 | benign 閾値では陽性を出せない |
| `Transformer` | プロセス単位・10分ごと | `top10 miss ratio @ p95` | 0.000 | 0.000 | 0.000 | 0 | LSTM 同様に陽性を出せない |
| `LSTM AutoEncoder` | プロセス単位・10分ごと | `max reconstruction score @ p95` | 0.000 | 0.000 | 0.000 | 2 | 陽性は出ても attack 系列に結び付かない |
| `LSTM` | ユーザ単位・10分ごと | `top10 miss ratio @ p95` | 0.000 | 0.000 | 0.000 | 3 | benign 閾値では陽性が出ても TP につながらない |
| `Transformer` | ユーザ単位・10分ごと | `top10 miss ratio @ p95` | 0.000 | 0.000 | 0.000 | 3 | LSTM 同様に benign 閾値では TP 0 |
| `LSTM AutoEncoder` | ユーザ単位・10分ごと | `max reconstruction score @ p95` | 0.000 | 0.000 | 0.000 | 0 | 閾値を置くと陽性自体が出ない |

### 3.13 deep 系を不採用とした理由

- `LSTM / Transformer` は探索段階の生スコアでは attack を広く拾うが、`cp10 / cu10` のどちらでも benign 由来の `p95` 閾値では TP につながらなかった
- `AutoEncoder` は再構成誤差スコア自体は出るが、`cu10` では陽性を出せず、`cp10` でも attack 系列に結び付かなかった
- 一方で、`IsolationForest + ユーザ単位・10分ごと + 1-2gram TF-IDF` は同じ benign-only 条件で `F1=0.667, Recall=0.667, Precision=0.667` を維持できた

したがって、**2026-05-07 時点では deep 系は `cp10 / cu10` の両方で first pass の採用候補から外し、`ユーザ単位・10分ごと + 1-2gram TF-IDF + IsolationForest` を採用する**。

### 3.14 first pass でどこまで絞れたか

first pass の後でも、攻撃近傍の正常文脈を残すためにログ量はなお大きい。

| 段階 | 何をしたか | 残った対象 | 総ログ数 | 攻撃ログ数 | 正常ログ数 | 意味 |
| --- | --- | --- | ---: | ---: | ---: | --- |
| 1. 元データ | attack day の全ログをそのまま対象にした | `S3` の全ログ | 257,887 | 292 | 257,595 | 絞り込み前の全体量 |
| 2. first pass | ログをユーザ単位・10分ごとの系列にまとめ、`IsolationForest` で怪しい系列だけを抽出した | 陽性 3 系列に含まれるログ | 118,495 | 286 | 118,209 | 18 系列から 3 系列まで絞れたが、系列内には正常ログも多く残る |
| 3. first pass の内訳確認 | 残った 3 系列を、攻撃を含む系列と含まない系列に分けて確認した | 真陽性 2 系列に含まれるログ | 約94,815 | 286 | 94,529 | 攻撃を含む系列の中にも、攻撃近傍の正常ログが大量に含まれている |

### 3.15 second pass でやりたいこと

second pass の役割は、first pass で残った `118,495 log` を `100 event chunk` のような小窓に分け、  
**「どこから読むべきか」** を決めることである。

したがって second pass では、

- chunk-level の局所化
- chunk-level の優先順位付け
- 読量削減と攻撃保持の両立

を評価する。

### 3.16 second pass の rule-free 比較

first pass の陽性 3 系列に含まれる `118,495 log` を対象に、  
`100 event chunk` へ分割した上で、次の6手法を second pass 候補として比較した。

1. `chunk-level IsolationForest`
2. `chunk-level OneClassSVM`
3. `chunk-level LOF`
4. `kNN distance`
5. `chunk-level SGDOneClassSVM`
6. `SVD reconstruction error`

比較条件は次の通りである。

- 対象: first pass で残った陽性 3 系列
- chunk サイズ: `100 event`
- 入力表現: `1-2gram TF-IDF`
- 評価対象: `top1 / top3 / top10 / top50 chunk`
- 評価軸:
  - 読量削減率
  - 攻撃保持率
  - 正常文脈保持量

| 方法 | スコアの考え方 | first attack rank | top10 chunk 総イベント数 | top10 attack event | threshold ベースの挙動 | 読み |
| --- | --- | ---: | ---: | ---: | --- | --- |
| `chunk-level IsolationForest` | benign chunk から外れる chunk を上位化 | 24 | 1,000 | 0 | 11 chunk を陽性にしたが attack chunk 0 | first pass と一貫するが、局所化は弱い |
| `chunk-level OneClassSVM` | 正常 chunk 境界の外側にある chunk を上位化 | 2 | 1,000 | 30 | 35 chunk を陽性にし、42 attack event を保持 | top10 時点でも attack をある程度保持できる |
| `chunk-level LOF` | 近傍密度が低い chunk を上位化 | 1 | 1,000 | 38 | 175 chunk を陽性にし、109 attack event を保持 | 最も早く attack に届くが、拾いすぎやすい |
| `kNN distance` | 正常 chunk から遠い chunk を上位化 | 23 | 1,000 | 0 | `p95` では陽性 0。top50 で attack 到達 | ランキングの初動が弱く、今回の条件では不利 |
| `chunk-level SGDOneClassSVM` | 線形 one-class 境界からの外れを上位化 | 24 | 1,000 | 0 | `p95` では陽性 0。top50 で attack 到達 | 高速だが今回の sparse chunk では差がつかなかった |
| `SVD reconstruction error` | 低次元再構成誤差が大きい chunk を上位化 | 2 | 1,000 | 1 | 32 chunk を陽性にし、39 attack event を保持 | 古典的手法としては有効だが top10 の密度は低い |

### 3.17 second pass 比較の読み

- second pass は、少なくとも **手作業ヒューリスティックなしで比較可能な形** まで整理できた
- `LOF` は `top1 chunk` で attack に到達し、`OneClassSVM` は `top3 chunk` までに attack に到達した
- `SVD reconstruction error` も `first attack rank = 2` と一定の有効性を示した
- 一方で `IsolationForest`、`kNN`、`SGDOneClassSVM` は `top10 chunk` では attack に届かず、chunk 局所化には向かなかった
- したがって、second pass では **first pass と同じ `IsolationForest` をそのまま使うより、chunk 局所化に特化した `LOF / OneClassSVM`、補助候補として `SVD` の方が有利** である

このため、2026-05-07 時点では second pass は

- 実装と比較はできている
- `LOF / OneClassSVM / SVD` なら attack への到達順を改善できる
- ただし、`LOF` は拾いすぎ、`OneClassSVM` はやや保守的、`SVD` は top10 の attack 密度が低い、というトレードオフがある

と整理するのが妥当である。

### 3.18 現時点での整理

これまでの second pass は、`100 event chunk` に対するヒューリスティック寄りの再順位付けであった。  
今回これをやめて、**同じ first pass 出力に対して、同じ chunk 切り・同じ入力表現で one-class / 距離ベース手法を比較する形** に置き換えた。

そのため、現時点では次のように扱う。

- first pass は主結果
- second pass は補助結果として提示できる
- second pass の暫定候補は `LOF` または `OneClassSVM`、補助候補として `SVD` である

## 4. 現在の実験方針

### 4.1 first pass を主結果とする

現時点で最も筋が通っている主結果は、次である。

- 系列の作り方: `ユーザ単位・10分ごと`
- 入力表現: `1-2gram TF-IDF`
- 判定器: `IsolationForest`
- 閾値: benign validation 由来の `p95`

この構成は、

- 系列数を `18 -> 3` に絞れる
- `TP 2 / FP 1` まで落とせる
- 攻撃近傍の正常文脈を多く残せる

という意味で、今回の目的に最も合っている。

### 4.2 second pass は rule-free 比較まで完了

second pass については、手作業ヒューリスティックを使わず、

- `chunk-level IsolationForest`
- `chunk-level OneClassSVM`
- `chunk-level LOF`
- `kNN distance`
- `chunk-level SGDOneClassSVM`
- `SVD reconstruction error`

を同一条件で比較できる状態になった。  
今後は、この中から `LOF`、`OneClassSVM`、必要なら `SVD` のどれを採用するかを、読量削減率と攻撃保持率の観点で詰める。

## 5. 現時点の弱点

### 5.1 deep 系との比較はまだ公平でない

- `forecasting / reconstruction` 系は「時系列そのもの」
- `one-class` 系は `TF-IDF`

という違いがあるため、deep 系との比較は現時点でも厳密な公平比較ではない。  
したがって、今回の正式結果は **one-class 系の統一条件比較を中心に述べる**。

### 5.2 second pass の一般化ができていない

- first pass で怪しい系列までは絞れる
- second pass も rule-free に比較できるようになった
- ただし、`LOF` と `OneClassSVM`、必要なら `SVD` のどれを採用するか、また `top-k` をどこに置くかはまだ未確定である

今後は、`100 event chunk` を前提にしたまま、

- `LOF` を使って早く attack に到達する方針
- `OneClassSVM` を使って読み量を抑える方針
- `SVD` を使って古典的再構成誤差で安定化を狙う方針

のどちらが今回の研究目的により合うかを詰める必要がある。
