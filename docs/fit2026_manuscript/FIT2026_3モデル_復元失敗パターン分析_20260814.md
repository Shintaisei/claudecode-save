# 3モデルの復元失敗パターン分析

作成日: 2026-08-14

## 1. 結論

再採点後は、失敗を単なる不正解ではなく、Gold stepの欠落、対象の誤り、主体の誤り、関係の誤り、主体・対象の役割逆転、Goldに対応しない付加、値の誤り、重複、順序逆転として分離できる。特に重要なのは、Gold側の復元失敗と、CLOUSEAUが余分に出したclaimの誤りを別々に数えることである。

## 2. Gold step側の復元パターン

主体・行動・対象の最終スコアを3ビットとして分類した。たとえば `110` は主体と行動が正しく、対象だけが誤っていることを表す。

| パターン | 定義 | 件数 |
|---|---|---:|
| `COMPLETE_SAO` | 主体・行動・対象を完全復元 | 469/1571（29.9%） |
| `STEP_OMISSION` | Gold step全体を発見できなかった | 842/1571（53.6%） |
| `OBJECT_ERROR` | 主体と行動は正しいが対象を誤った／欠いた | 115/1571（7.3%） |
| `SUBJECT_ERROR` | 行動と対象は正しいが主体を誤った／欠いた | 52/1571（3.3%） |
| `RELATION_ERROR` | 主体と対象は正しいが関係を誤った | 18/1571（1.1%） |
| `ACTION_ONLY` | 行動だけを捉え、主体・対象を誤った／欠いた | 33/1571（2.1%） |
| `SUBJECT_ONLY` | 主体だけを捉えた | 39/1571（2.5%） |
| `OBJECT_ONLY` | 対象だけを捉えた | 3/1571（0.2%） |

ここでの `RELATION_ERROR` 18件は、主体と対象の両方が正しく、行動だけが誤った純粋な関係誤認である。後述のclaim側 `WRONG_RELATION` 154件は、値の誤りや重複などを併発したclaimも含むため、同じ分母の数値ではない。

## 4. CLOUSEAU出力側の誤りパターン

全1384 candidate claimのうち、Gold stepへ対応付けられなかったclaimは478件である。claimには複数の誤りが重なることがあるため、以下のflag件数は重複を含む。

| flag | 意味 | 件数 |
|---|---|---:|
| `UNSUPPORTED_OR_NEARBY` | Gold外の近傍事象、またはGoldで支持できない付加 | 318 |
| `UNSUPPORTED` | 採点証拠で支持できない付加（捏造候補） | 68 |
| `WRONG_VALUE` | 主体・対象の値、PID、パス、IPなどの誤り | 383 |
| `WRONG_RELATION` | 主体と対象の間の関係を別の行動として解釈 | 154 |
| `WRONG_COMPONENT` | 情報を主体・行動・対象の誤った欄へ配置 | 125 |
| `DUPLICATE` | 同一関係の重複・冗長出力 | 180 |
| `SUBJECT_OBJECT_REVERSAL` | 主体と対象を逆に配置した高確度候補 | 7 |

Goldへ対応しなかった478 claimのうち、376件は主分類がGold非対応の付加であり、未対応claimの78.7%を占めた。`UNSUPPORTED`や`UNSUPPORTED_OR_NEARBY`は、その時点でGoldに対応しないことを示す。これを捏造と断定するには、元ログにも該当関係が存在しないことを追加確認する必要がある。そのため本分析では「Gold非対応の付加」または「捏造候補」と呼ぶ。

| モデル・領域 | claim数 | Gold非対応の付加 | 関係誤認 | 値・実体誤り | 主体対象逆転 |
|---|---:|---:|---:|---:|---:|
| gpt-4.1-mini・正常 | 263 | 1 | 54 | 118 | 2 |
| gpt-4.1-mini・攻撃 | 299 | 155 | 3 | 18 | 0 |
| gpt-5.4-mini・正常 | 114 | 1 | 25 | 45 | 1 |
| gpt-5.4-mini・攻撃 | 173 | 92 | 4 | 11 | 4 |
| gpt-5.5・正常 | 269 | 3 | 67 | 84 | 0 |
| gpt-5.5・攻撃 | 266 | 124 | 0 | 0 | 0 |

Gold step側は全領域で同じ主体・行動・対象rubricを使っているため、正常・攻撃間を比較しやすい。一方、claim側のfalse-positive flagは元の正常・攻撃台帳のラベル運用を引き継いでいる。したがって、claim側の表は誤りの型を把握する用途に使い、領域間の比率差をそのまま性能差と断定しない。

## 6. 順序の失敗

全1187 Gold pairのうち、正順は298件、実際の逆順は21件、endpoint stepの欠落により評価不能だったものは868件、複合claimにまとめられて評価不能だったものは0件である。

この分類により、順序失敗の大部分が『並べ方を間違えた』のではなく、『必要なstepを発見できず順序を評価できなかった』こととして説明できる。

## 7. 考察で使う推奨分類

研究発表では、まずGold側を①完全復元、②step欠落、③対象誤り、④主体誤り、⑤関係誤り、⑥部分断片に分類する。その後、出力側の原因として⑦主体・対象逆転、⑧Gold非対応の付加、⑨値の誤り、⑩重複、⑪順序逆転を説明する。この二層構造にすると、復元できなかった結果と、CLOUSEAUがどのように間違えたかを混同せずに考察できる。
