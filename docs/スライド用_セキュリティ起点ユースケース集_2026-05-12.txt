- 各ユースケースで

1. 研究上の前提
- 今回の異常検知入力は主に Security ログ由来の file access 系テンプレート列である
- 代表 EventID は 4656, 4663, 4658 であり、一部 4660, 4690, 4688, 5156 も見える
- したがって「異常検知が何に反応したか」を Security 観点で説明するのが自然である
- 一方で、process 名だけでは弱いケースがあるため、起点には ObjectName / TargetFilename / TargetObject などの対象情報を優先したい


2. Security 生ログで起点になりうる軸
- 高特異性で使いやすい
  - 具体的なファイルやディレクトリパス
  - 具体的な生成プロセス名 NewProcessName
  - 具体的な通信先 IP / Port
- 中特異性で条件付きで使いやすい
  - ProcessName + SubjectUserName + SubjectLogonId
  - ProcessName + AccessMask / AccessList + ObjectName
  - PrivilegeList + ProcessName
- 低特異性で単独では弱い
  - ProcessName 単独
  - ObjectType 単独
  - TargetUserName / LogonType 単独
- 今回の raw 走査では ServiceName は有効な主起点としてほぼ使えなかった

5. UC01 explorer.exe
- 異常検知での見え方
  - host: win-32-h1
  - 主体: aalsahee
  - session bucket: 2022-07-19 14:30Z
  - sequence rank: 6
  - micro rank: 7
  - LOF score: 9486381958.474821
  - 10 event 中の出現: explorer.exe 3 件
  - 10 event の構成: 0 attack / 10 normal
  - 解釈上は top10 core の強い正常寄り偽陽性候補
- raw Security の代表例
  - 2022-07-17T21:06:24.9811227Z
  - EventID 4663
  - SubjectUserName: aalsahee
  - ObjectName: C:\Users\aalsahee\AppData\Roaming\Microsoft\Windows\Recent\shared_logs.lnk
  - AccessMask: 0x6
  - 同時系列で 4656, 4663, 4660, 4658 がまとまって出ている
  - 近い例として
    - msft-security-day3.evtx.lnk
    - AutomaticDestinations\1b4dd67f29cb1962.automaticDestinations-ms
    が見えている
- スライド上の行動説明
  - 対話ユーザ aalsahee 文脈で Explorer が Recent / Jump List 系オブジェクトにアクセスしている
  - したがって「単なる explorer.exe」ではなく「直近に開いたファイルやショートカットに関連する操作」の候補として書ける
- 起点として使えるもの
  - shared_logs.lnk のような具体パス
  - Recent フォルダ配下
  - AutomaticDestinations の具体ファイル
- 探索成立性
  - 高い
  - ProcessName 単独ではなく、Recent / LNK / AutomaticDestinations の具体パスを起点にすればかなり追いやすい
- スライドで強調したい点
  - explorer.exe でも ObjectName が見えれば急に意味が出る
  - process 起点単独より file path 起点が強い

13. 発表での大きな結論
- Security 生ログだけでも、起点として使える情報は process 名しかないわけではない
- 特に有効なのは
  - ObjectName / TargetFilename / TargetObject
  - NewProcessName
  - DestAddress / DestPort
- 7 候補の中では
  - まとまりやすい: explorer.exe, winword.exe, firefox.exe
  - 条件付きでいける: repmgr.exe
  - 背景反復が強い: repwmiutils.exe, spoolsv.exe, tpautoconnsvc.exe
- したがって「どういう起点なら正常行動を復元しやすいか / しにくいか」を結論にできる


14. 1 枚に圧縮するなら使える要約文
- explorer.exe は Recent / Jump List 系の具体パスが見えるため、単なる process ではなく「直近ファイル操作」の起点として扱える
- winword.exe は Content.Word や tmp.cvr など文書一時ファイルが見えるため、文書閲覧・一時展開の正常ユースケースとして説明しやすい
- firefox.exe は profile 配下の telemetry / session ファイルが見えるため、ブラウザ通常利用に伴う状態保存として復元可能である
- repmgr.exe は Carbon Black event ファイル群にアクセスしており、支援的・収集的な手続型の正常動作として読むのが自然である
- repwmiutils.exe, spoolsv.exe, tpautoconnsvc.exe は具体パスは見えるが、背景サービス反復が強く、正常行動の意味づけは相対的に難しい
