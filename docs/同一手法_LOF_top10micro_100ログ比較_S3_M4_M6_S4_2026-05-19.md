# 同一手法 LOF top10 micro 100ログ比較: S3 / M4 / M6 / S4

日付: 2026-05-19

## 1. この比較でそろえた条件

- `10ログ単位の micro-chunk` を対象とする
- 各 scenario で second pass の高スコア候補から third pass を同じ `LOF` で実施する
- `LOF top10 micro-chunk` を採用し、`10 x 10 = 100ログ` を比較対象とする
- 分類軸は `attack label を1件でも含む micro-chunk` と `完全正常 micro-chunk` の2区分だけにそろえる

## 2. 比較結果

| scenario | top10 micro 内 attack-mixed | top10 micro 内 normal-only | 100ログ中 attack | 100ログ中 normal | first attack rank |
| --- | ---: | ---: | ---: | ---: | ---: |
| `S3` | `5` | `5` | `11` | `89` | `1` |
| `M4` | `0` | `10` | `0` | `100` | `None` |
| `M6` | `0` | `10` | `0` | `100` | `None` |
| `S4` | `0` | `10` | `0` | `100` | `398` |

## 3. scenario ごとの見え方

### S3

- `top10 micro` の半分は attack を含む
- ただし残り半分は `0 / 10` の完全正常で、`tpautoconnect.exe + repmgr.exe / explorer.exe / winword.exe` が見える
- つまり `S3` は attack-near 文脈の中から正常候補を拾うシナリオとして読むのが自然

代表:

- `chunk330 micro05`: `1 / 9`, `payload.exe, tpautoconnect.exe, csrss.exe`
- `chunk325 micro05`: `3 / 7`, `payload.exe, tpautoconnect.exe`
- `chunk204 micro02`: `0 / 10`, `tpautoconnect.exe, repmgr.exe`
- `chunk244 micro08`: `0 / 10`, `tpautoconnect.exe, explorer.exe`
- `chunk203 micro07`: `0 / 10`, `tpautoconnect.exe, winword.exe`

### M4

- `top10 micro` がすべて `0 / 10`
- `100ログ` 全体で attack label は `0`
- 上位は `tpautoconnect.exe` 反復と `tshark.exe` 反復が中心

代表:

- `chunk174 micro04`: `0 / 10`, `tpautoconnect.exe`
- `chunk174 micro05`: `0 / 10`, `tpautoconnect.exe, svchost.exe`
- `chunk007 micro02`: `0 / 10`, `tshark.exe`

### M6

- `top10 micro` がすべて `0 / 10`
- `100ログ` 全体で attack label は `0`
- `cmd.exe + tpautoconnect.exe` の混在1本と、`tshark.exe` 反復が主成分

代表:

- `chunk022 micro06`: `0 / 10`, `cmd.exe, tpautoconnect.exe`
- `chunk007 micro02`: `0 / 10`, `tshark.exe`
- `chunk009 micro08`: `0 / 10`, `tshark.exe`

### S4

- `top10 micro` がすべて `0 / 10`
- `100ログ` 全体で attack label は `0`
- ただし候補母集団全体では attack が後順位に残っていて、`first attack rank = 398`
- 上位は `wmiprvse.exe`, `upd.exe`, `scanhost.exe` のまとまり

代表:

- `chunk199 micro00`: `0 / 10`, `wmiprvse.exe`
- `chunk180 micro00`: `0 / 10`, `upd.exe`
- `chunk180 micro05`: `0 / 10`, `scanhost.exe`

## 4. 今回の結論

- `同一手法` でそろえても、`S3` だけが top10 micro の時点で attack を含む
- `M4 / M6 / S4` は `LOF top10 micro = 100ログ` の時点で完全正常
- したがって、「異常検知で高スコアだった 100ログから正常候補を拾う」という見せ方は `S3` では attack-near 型、`M4 / M6 / S4` では pure-normal 型として分けて説明するのがよい
