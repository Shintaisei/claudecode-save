# CLOUSEAU を使う追跡実験計画

更新日: 2026-05-10

## 1. 目的

- `CLOUSEAU` を使って、起点から後続ログをどこまで追跡できるかを評価する
- 起点の種類によって `追跡可能 / 半追跡可能 / 追跡困難` が分かれることを示す
- 追跡結果を `正常 / 攻撃 / 判定不能` に分け、どの起点で `判定不能` が出やすいかを見る

## 2. いま足りないこと

- 現在の有力候補は `explorer.exe / winword.exe / repmgr.exe` の3種で、実験項目としては少ない
- 9マスで見せたいなら、起点候補を意図的に増やす必要がある
- `CLOUSEAU` 用の答えデータも別で用意しないといけない

## 3. 9マスの基本軸

今回の 9 マスは、これまでの研究方針をそのまま使うのが自然。

- 横軸: 正常行動種別
  - `単発操作型`
  - `手続型`
  - `背景動作型`
- 縦軸: 起点特異性
  - `高`
  - `中`
  - `低`

## 4. CLOUSEAU 実験に合わせた9マスの読み替え

この実験では、各マスを「起点として CLOUSEAU に渡す POI の型」として扱う。

| 起点特異性 \ 正常行動 | 単発操作型 | 手続型 | 背景動作型 |
| --- | --- | --- | --- |
| `高` | 単独でも意味が明確な POI | 前後の連鎖で意味が立つ POI | 背景だが異常に上位化された POI |
| `中` | 少し周辺文脈が必要な POI | 周辺文脈がかなり必要な POI | ノイズに近いが追跡は試せる POI |
| `低` | broad 候補から拾う POI | broad 候補から拾う連鎖 POI | ほぼ対照群 |

## 5. 今ある候補と足りないマス

### 5.1 すでにある候補

| process | 現在の位置づけ | 備考 |
| --- | --- | --- |
| `explorer.exe` | `高 x 単発操作型` | ファイル操作、追跡しやすい |
| `winword.exe` | `高 x 単発操作型` | 文書閲覧、追跡しやすい |
| `repmgr.exe` | `高 x 手続型` | 文書関連アクセス連鎖、半追跡可能 |

### 5.2 足りないマス

- `高 x 背景動作型`
- `中 x 単発操作型`
- `中 x 手続型`
- `中 x 背景動作型`
- `低` 行のほぼ全部

## 6. 9マスを埋めるための候補集め方

### 6.1 高特異性

- いまの `LOF top10 micro-chunk`
- ここから `explorer.exe / winword.exe / repmgr.exe`
- 背景型を足すなら `tpautoconnsvc.exe` や `spoolsv.exe` 帯を third pass

### 6.2 中特異性

- `LOF top100` のうち `rank 42-47`
- `browser` 系の `firefox.exe`
- `rank 74-100` の `spoolsv.exe / tpautoconnsvc.exe / repwmiutils.exe`

### 6.3 低特異性

- second pass 上位ではなく、broader な候補帯から少数だけ取る
- ここは実験上の対照群として使う
- 追跡が破綻しやすい例を置く役割

## 7. 実験候補の最小セット

9マスを完全に埋める前に、まずは小さく始めるなら次の 6 種が現実的。

| process | 想定マス | 取得元 |
| --- | --- | --- |
| `explorer.exe` | `高 x 単発操作型` | 既存 |
| `winword.exe` | `高 x 単発操作型` | 既存 |
| `repmgr.exe` | `高 x 手続型` | 既存 |
| `firefox.exe` | `中 x 単発操作型` | `rank 43-47` を third pass |
| `repwmiutils.exe` | `中 x 手続型` か `中 x 背景動作型` | `rank 74-100` |
| `spoolsv.exe` or `tpautoconnsvc.exe` | `中 x 背景動作型` | `rank 74-100` |

これでまず 5-6 マスを埋められる。

## 8. 実験の単位

### 8.1 1 ケース

- 1 POI = 1 起点 event または 1 起点 micro-chunk
- その POI を `CLOUSEAU` に渡して追跡させる

### 8.2 1 ケースで見る出力

- 追跡された主要プロセス
- 追跡されたファイル
- 追跡されたネットワーク先
- 出力レポートの要約
- 最終判定
  - `正常`
  - `攻撃`
  - `判定不能`
- 追跡可能性
  - `追跡可能`
  - `半追跡可能`
  - `追跡困難`

## 9. 答えデータの作り方

ここはかなり重要で、`CLOUSEAU` の評価用に ground truth を別で持つ必要がある。

### 9.1 最低限の答えデータ

各起点について、次を手で付ける。

- `poi_type`
- `poi_process`
- `expected_behavior_type`
  - `単発操作型`
  - `手続型`
  - `背景動作型`
- `expected_traceability`
  - `追跡可能`
  - `半追跡可能`
  - `追跡困難`
- `expected_outcome`
  - `正常`
  - `攻撃`
  - `判定不能`

### 9.2 理想的な答えデータ

さらに次まで付けるとよい。

- `expected_related_processes`
- `expected_related_files`
- `expected_related_time_window`
- `notes`

### 9.3 形式

CSV で十分。

| case_id | poi_process | poi_rank | behavior_type | traceability | outcome | related_processes | related_files | notes |
| --- | --- | ---: | --- | --- | --- | --- | --- | --- |

## 10. 評価方法

### 10.1 主要評価

- `CLOUSEAU` が後続の関連ログをどこまで取れたか
- 起点ごとに `追跡可能 / 半追跡可能 / 追跡困難` が分かれるか
- 起点ごとに `判定不能` の出やすさが違うか

### 10.2 実験結果の表

| 起点 | 件数 | 追跡可能 | 半追跡可能 | 追跡困難 | 正常 | 攻撃 | 判定不能 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `explorer.exe` | `n` | `n` | `n` | `n` | `n` | `n` | `n` |
| `winword.exe` | `n` | `n` | `n` | `n` | `n` | `n` | `n` |
| `repmgr.exe` | `n` | `n` | `n` | `n` | `n` | `n` | `n` |
| `firefox.exe` | `n` | `n` | `n` | `n` | `n` | `n` | `n` |
| `spoolsv.exe` | `n` | `n` | `n` | `n` | `n` | `n` | `n` |

### 10.3 9マス結果の表

| 起点特異性 \ 正常行動 | 単発操作型 | 手続型 | 背景動作型 |
| --- | --- | --- | --- |
| `高` | 成功率 / 判定不能率 | 成功率 / 判定不能率 | 成功率 / 判定不能率 |
| `中` | 成功率 / 判定不能率 | 成功率 / 判定不能率 | 成功率 / 判定不能率 |
| `低` | 成功率 / 判定不能率 | 成功率 / 判定不能率 | 成功率 / 判定不能率 |

この形なら 9 マスを単なる分類表で終わらせず、`CLOUSEAU` の追跡性能表として使える。

## 11. いちばん現実的な進め方

### 段階 1

- まず 3-6 種の起点を集める
- 各起点について 2-3 ケースだけ答えデータを作る
- `CLOUSEAU` を少数ケースで試す

### 段階 2

- `firefox.exe` と `spoolsv.exe / tpautoconnsvc.exe` を追加
- 9マスのうち中段まで埋める

### 段階 3

- 必要なら低特異性の対照群を追加
- `判定不能` が出やすい条件を分析する

## 12. 今のおすすめ

- いきなり 9 マス完全制覇を目指すより、
  - `高 x 単発操作型`
  - `高 x 手続型`
  - `中 x 単発操作型`
  - `中 x 背景動作型`
  の 4-6 マスくらいから始めるのがよい
- そのうえで、答えデータを少数でも先に作る
- `CLOUSEAU` を回してみて、どの型で `判定不能` が出るかを確認する

この順番にすると、実験がかなり組み立てやすい。
