## 3. どの層に何が残っているか

### 3.1 Wazuh alert 層

Wazuh 側では次のような列が直接使える。

- `rule_description`
- `rule_id`
- `rule_level`
- `data_win_eventdata_image`
- `data_win_eventdata_parentImage`
- `data_win_eventdata_commandLine`
- `data_win_eventdata_targetFilename`

つまり、**起点アラートとして見せるには最初の入口として十分強い**。

### 3.2 ProcessCreate 層

ProcessCreate 側では次が使える。

- `Image`
- `CommandLine`
- `ParentImage`
- `ParentCommandLine`
- `User`
- `TimeCreated`

つまり、**正常行動の手続の流れ** を一番説明しやすい。

### 3.3 FileCreate 層

FileCreate 側では次が使える。

- `Image`
- `TargetFilename`
- `Bucket`
- `User`
- `TimeCreated`

つまり、**特定ファイルパスを起点にする高特異性ケース** を説明しやすい。

### 3.4 Registry 層

Registry 側では次が使える。

- `Image`
- `TargetObject`
- `Details`
- `Bucket`
- `User`
- `TimeCreated`

つまり、**Run key / protocol handler / RunOnce** のようなレジストリ由来の起点が扱える。

### 3.5 Security 層

Security 側は今回見た範囲では、

- `4624`
- `4672`

などのログオン・特権付与系が中心で、今回の正常行動復元の主戦場は Sysmon 系のほうだった。

## 6. 今回の結論

### 6.1 起点になりそうなもの

今回の raw log から、起点としてそのまま強いのは次。

- `install_choco_software.ps1`
- `logs.zip`
- `C:\Windows\Temp\GUR*.exe`
- `HKLM\...\Run\Dropbox`
- `HKCR\dropbox-client\shell\Open\Command`
- `HKU\...\Run\Discord`
- `OneDrive.CameraRoll.Import\shell\open\command`
- `C:\Windows\Temp\secexport.cfg`

### 6.2 正常行動の詳細まで追えるもの

行動のまとまりとしてかなり追えるのは次。

- 収集スクリプト実行とログ圧縮
- Dropbox の導入・更新・Temp EXE 生成
- Wazuh agent による discovery / SecEdit
- OneDrive の更新・常駐起動・RunOnce 更新
- Discord の導入・起動・自動起動登録

### 6.3 起点として弱いもの

raw log にも残っているが、そのまま起点にしづらいのは次。

- `svchost.exe` 単独
- `Windows logon success`
- `taskschd.dll` のうち対象 process が広すぎるもの
