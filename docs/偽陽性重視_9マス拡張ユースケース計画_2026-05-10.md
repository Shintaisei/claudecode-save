# 偽陽性重視の9マス拡張ユースケース計画

更新日: 2026-05-10

## 1. 目的

- 9マスを埋めるために、現在の `top10 sequence` を起点にユースケース候補を拡張する
- ただし目的は「一般的な正常行動」収集ではなく、**異常検知で偽陽性になりやすい正常行動** を集めること
- `CLOUSEAU` 実験では、この偽陽性寄りユースケースを POI として追跡可能性を測る

## 2. この方針で大事なこと

- 9マスを均等に埋めること自体が目的ではない
- **異常検知で上に来やすい正常行動** を優先する
- その結果として、埋まりやすいマスと埋まりにくいマスがあってよい
- 拡張するときも、母集団はできるだけ **`10 sequence` の異常検知結果** に固定する

## 3. いまの top10 sequence の意味

現在の `LOF top10 chunk -> top10 micro-chunk` から見えている正常寄り候補は次の3つ。

- `explorer.exe`
- `winword.exe`
- `repmgr.exe`

この3つは、どれも

- 正常行動として意味がある
- 実際に異常検知で上位に来ている
- 周辺に `tpautoconnect.exe` などのノイズが混ざる

という点で、**偽陽性ユースケースの核** としてかなりよい。

## 3.1 拡張の前提

- ユースケース拡張は、できるだけ `10 sequence` の異常検知結果から行う
- つまり「あとから broad に正常ログを探す」のではなく、
  - まず `10 sequence` を固定
  - その中で順位を付ける
  - その順位の高いものから候補化する
  という順にする
- これなら「偽陽性になりやすい正常行動を、異常検知結果から自然に拾った」と言いやすい

## 3.2 10 sequence の中でどう順位を付けるか

`10 sequence` の中で候補順位を出すときは、次の 3 段階が自然。

1. `sequence rank`
   - second pass の rank
   - まず大きな優先度はここで決まる

2. `micro rank`
   - third pass の rank
   - 同じ sequence の中で、どの局所塊がより異常検知に引っかかったかを見る

3. `usecase value`
   - `payload.exe` と `tpautoconnect.exe` を除いた残りプロセスの説明しやすさ
   - `explorer.exe / winword.exe / repmgr.exe / firefox.exe / repwmiutils.exe / spoolsv.exe / tpautoconnsvc.exe`
     のような、偽陽性ユースケースにしやすいものを上げる

## 3.3 最終的な候補順位の考え方

最終候補は、次のような順で並べる。

| 優先度の軸 | 何を見るか | 意味 |
| --- | --- | --- |
| `1` | `sequence rank` | 大域的に異常検知でどれだけ上に来たか |
| `2` | `micro rank` | その sequence 内でどれだけ上に来たか |
| `3` | 非coreプロセス | 偽陽性ユースケースとして説明可能か |

つまり、候補は

- `異常検知で上位`
- `10 sequence 内でもさらに上位`
- `正常行動として説明できる`

の 3 条件で採る。

## 4. 偽陽性ユースケースとして欲しいもの

今回ほしいのは、次のどれかに当てはまるもの。

1. 正常だが、攻撃っぽいプロセス列やアクセス列に見える
2. 正常だが、背景ノイズと混ざって異常スコアが上がる
3. 正常だが、単独で見ると意味が弱く判定不能になりやすい
4. 正常だが、攻撃近傍にあるため誤検知されやすい

## 5. 9マスを埋めるための拡張元

### 5.1 まず残す核

- `rank 1-10`
- ここは attack-near と seed 候補が混ざる最重要帯
- `explorer.exe / winword.exe / repmgr.exe` はここから採る

### 5.2 次に足す帯

- `rank 42-47`
- `browser / user-file` が再登場する帯
- `firefox.exe` 系の偽陽性ユースケース候補を足せる

### 5.3 背景動作型を足す帯

- `rank 74-100`
- `spoolsv.exe / tpautoconnsvc.exe / repwmiutils.exe`
- 背景動作型で偽陽性になりやすい候補を足せる

### 5.4 基本スキップ帯

- `rank 11-40`
- ほぼ `tpautoconnect.exe` 反復
- 背景ノイズとしては重要だが、ユースケースそのものとしては薄い

## 6. 9マスへの割り当て方

| 起点特異性 \ 正常行動 | 単発操作型 | 手続型 | 背景動作型 |
| --- | --- | --- | --- |
| `高` | `explorer.exe`, `winword.exe` | `repmgr.exe` | `候補不足` |
| `中` | `firefox.exe` | `repwmiutils.exe` | `spoolsv.exe`, `tpautoconnsvc.exe` |
| `低` | broad user-file | broad office chain | broad service noise |

この表では、`低` は無理に増やすより対照群として少数でよい。

## 6.1 10 sequence ベースでの候補化ルール

9マスを埋めるときも、次のルールを守る。

1. まず `10 sequence` を対象にする
2. 各 sequence の中で `micro rank` を出す
3. `payload.exe` と `tpautoconnect.exe` を除いたプロセスを見る
4. その中から偽陽性ユースケースになりやすいものだけ採る

このルールにしておけば、9マスを埋めるために候補を広げても、
「異常検知結果から外れて恣意的に集めた」
という見え方をかなり減らせる。

## 7. 追加したいユースケース候補

### 7.1 単発操作型

- `explorer.exe`
  - ファイル操作
  - 偽陽性になりやすい理由:
    背景ノイズの中に局所的に見えるため

- `winword.exe`
  - 文書閲覧
  - 偽陽性になりやすい理由:
    単発出現でも意味が強く、周辺アクセスで異常っぽく見える

- `firefox.exe`
  - browser 操作
  - 偽陽性になりやすい理由:
    通信や一時ファイルアクセスが多く、攻撃近傍と紛れやすい

### 7.2 手続型

- `repmgr.exe`
  - 文書関連アクセス連鎖
  - 偽陽性になりやすい理由:
    単独では意味が弱く、文脈なしだと不審に見えやすい

- `repwmiutils.exe`
  - 管理・補助的な処理連鎖
  - 偽陽性になりやすい理由:
    システム寄りだが office/doc 帯に混ざると不自然に見えやすい

### 7.3 背景動作型

- `spoolsv.exe`
  - 印刷系の背景処理
  - 偽陽性になりやすい理由:
    ファイルアクセス量が多く、単独では不審に見えることがある

- `tpautoconnsvc.exe`
  - 仮想環境・プリンタ系の背景サービス
  - 偽陽性になりやすい理由:
    周期的だが局所的には異常スコアが上がりうる

## 8. ユースケースの採択基準

今回の目的に合わせると、採択条件は次の3つでよい。

1. 異常検知で一定以上に上位化されている
2. 正常行動として説明可能
3. 偽陽性になりやすい理由を文章で言える

つまり、

- ただ正常なだけの行動
- ただ珍しいだけの背景ノイズ

は優先度を下げる。

## 9. 実験用の最小ユースケース集合

まずは次の6つを作るのがちょうどよい。

| process | 想定マス | 偽陽性としての価値 |
| --- | --- | --- |
| `explorer.exe` | `高 x 単発操作型` | 高い |
| `winword.exe` | `高 x 単発操作型` | 高い |
| `repmgr.exe` | `高 x 手続型` | 高い |
| `firefox.exe` | `中 x 単発操作型` | 高い |
| `repwmiutils.exe` | `中 x 手続型` | 中 |
| `spoolsv.exe` or `tpautoconnsvc.exe` | `中 x 背景動作型` | 中 |

## 10. どう拡張するか

### 段階 1

- 既存の `top10 sequence` から
  - `explorer.exe`
  - `winword.exe`
  - `repmgr.exe`
  を確定

### 段階 2

- `10 sequence` の次点帯を追加する
- まずは `rank 42-47` を third pass
- その中で `firefox.exe` 候補に順位を付ける

### 段階 3

- `10 sequence` のさらに下の正常帯を追加する
- `rank 74-100` を third pass
- その中で `spoolsv.exe / tpautoconnsvc.exe / repwmiutils.exe` 候補に順位を付ける

### 段階 4

- 足りない低特異性マスは、必要なら broad 候補から少数だけ補う
