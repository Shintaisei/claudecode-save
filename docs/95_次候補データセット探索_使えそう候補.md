# 次候補データセット探索メモ

作成日: 2026-04-17

## 探索条件

ここまでの頓挫を踏まえ、次の条件で探した。

- 正常行動がある
- 攻撃行動もある
- できればWindowsまたはWindows系エンドポイントログ
- できればプロセス・認証・ネットワークを横断できる
- アラート起点や行動復元に近い分析ができる
- 「あとで主題に合わない」となりにくい

## 結論

最有力は **DARPA OpTC**。  
次点で **LANL Comprehensive Multi-Source Cyber-Security Events 2015** と **LANL Unified Host and Network Dataset 2017**。

ただし、どれもEVTX/Hayabusaに直接かける主データではない。

現実的な主軸案はこれ。

> OpTCを主データ候補として検証し、LANLを正常行動・企業ネットワーク文脈の比較対象にする。EVTX/Hayabusa評価は別枠でEVTX-ATTACK-SAMPLESやMordorを使う。

## 候補1: DARPA OpTC

URL:

- https://github.com/FiveDirections/OpTC-data
- https://fkie-cad.github.io/COMIDDS/content/datasets/optc/
- 修正版候補: https://entrepot.recherche.data.gouv.fr/dataset.xhtml?persistentId=doi:10.57745/UXCWOC

概要:

- Windows 10の大規模企業風テストベッド
- 1000ホスト規模、公開データは500ホスト分
- benign期間とred team評価期間がある
- エンドポイントテレメトリはeCAR形式
- Bro/Zeek系ネットワークログもある
- red team ground truthあり
- PowerShell Empire、lateral movement、exfiltration、malicious software updateなどを含む

良い点:

- Windows 10環境
- ホストログとネットワークログがある
- benignとmaliciousが同じ環境内にある
- 攻撃が単発ではなく複数日・複数段階
- プロセス、ファイル、スレッド、モジュール、ネットワークの関係をグラフ化しやすい
- 「行動復元」研究にかなり近い

危ない点:

- とにかく巨大。元データは1TB級、17Bイベント規模。
- EVTXではない。eCAR/JSON系。
- Hayabusa主軸にはならない。
- 正常行動は完全な現実業務ではなく、かなり合成的という指摘あり。
- ラベル付けはground truthから自分で行う必要がある。
- データ品質エラーがあり、2026年に修正版が出ている。

判定:

| 用途 | 判定 |
|---|---|
| 主データ候補 | Go |
| Windows端末行動復元 | Go寄り |
| 正常/攻撃比較 | Go |
| Hayabusa/EVTX | No-Go |
| すぐ軽く試す | Conditional |

最初にやるべきこと:

- 修正版OpTCから小さい日付・対象ホストだけ取得できるか確認
- red team ground truthで影響ホストを絞る
- まず1日・数ホストだけでeCAR構造を読む
- プロセス親子、ファイル、ネットワークの復元ができるか確認

## 候補2: LANL Comprehensive Multi-Source Cyber-Security Events 2015

URL:

- https://csr.lanl.gov/data/cyber1/
- https://www.osti.gov/biblio/1179829

概要:

- LANL企業ネットワークから58日分
- Windows認証イベント
- Windowsプロセス start/stop
- DNS
- NetFlow
- red teamイベント
- 約12GB圧縮、約16億イベント

良い点:

- 実組織由来の正常行動
- 58日分あり、正常行動の時間変化を見られる
- 認証、プロセス、DNS、NetFlowを横断できる
- red teamの悪性イベントがある
- 公開条件が明確

危ない点:

- EVTXではない。
- Windowsイベントログ由来だが、抽象化・匿名化されている。
- プロセス名などの意味が薄く、具体的な行動説明は難しい。
- red teamイベントが少ない。
- コマンドラインや詳細な親子関係は弱い。

判定:

| 用途 | 判定 |
|---|---|
| 正常行動の主軸 | Go |
| 攻撃検知モデル | Conditional |
| 行動復元 | Conditional |
| 具体的なWindows操作説明 | 弱い |
| Hayabusa/EVTX | No-Go |

向いている研究:

- 企業ネットワークにおける正常行動の時系列モデル
- 認証・DNS・NetFlow・プロセスを使った異常候補抽出
- red teamイベント周辺の関連ログ探索

## 候補3: LANL Unified Host and Network Dataset 2017

URL:

- https://lanl.ma.ic.ac.uk/data/2017/
- https://csr.lanl.gov/data/2017/

概要:

- LANL企業ネットワーク約90日分
- Windows host event logs由来
- NetFlow
- Windows EventIDとして、4624, 4625, 4648, 4688, 4689などを含む
- JSON Lines形式

良い点:

- 実企業由来の長期正常行動
- Windows Security Event系に近い
- EventID 4688/4689でプロセス開始/終了がある
- 認証イベントがかなり豊富
- 90日分で長期ベースラインが作れる

危ない点:

- 攻撃ラベルが弱い、または明確な攻撃シナリオがない。
- 匿名化されていて意味解釈は弱い。
- EVTXではない。
- Sysmonではない。

判定:

| 用途 | 判定 |
|---|---|
| 正常行動ベースライン | Go |
| 攻撃/正常分類 | No-Go寄り |
| 認証・プロセスの正常モデル | Go |
| SOCアラート復元 | 弱い |

使い方:

- 主データというより「正常行動とはどれくらい長期で揺れるか」の比較に使う。
- OpTCやLMDのNormalが不自然かどうかを照らす背景データにする。

## 候補4: Splunk BOTS

URL:

- BOTS 1.0: https://www.splunk.com/en_us/blog/security/boss-of-the-soc-scoring-server-questions-and-answers-and-dataset-open-sourced-and-ready-for-download.html
- BOTS 2.0: https://www.splunk.com/en_us/blog/security/boss-of-the-soc-2-0-dataset-questions-and-answers-open-sourced-and-ready-for-download.html

概要:

- Blue Team CTF用データセット
- Splunk取り込み前提
- Sysmon, Suricataなど複数ソース
- white noiseありのfull datasetとattack-only版がある
- Q&Aが付属

良い点:

- SOC調査の形に近い
- white noiseを含む版がある
- 複数ソースを横断できる
- 調査問題と答えがあるため、説明生成評価に使いやすい

危ない点:

- CTF用であり、研究用の厳密ラベルデータとは違う。
- Batman/Wayne Corpなど架空設定。
- Splunk依存が強い。
- 生EVTXではない可能性が高い。

判定:

| 用途 | 判定 |
|---|---|
| SOC調査デモ | Go |
| 説明生成/調査支援 | Go |
| 正常行動研究 | Conditional |
| Windowsイベント復元 | Conditional |
| 厳密ML分類 | 弱い |

## 最終おすすめ

### 第一候補: OpTC

今の研究テーマに一番近い可能性がある。

理由:

- Windows 10
- エンドポイント + ネットワーク
- benign + red team
- APT/LM/Exfiltration
- 行動復元・プロセス/ネットワーク関係分析に向く

最初の検証だけでよいので、全量ではなく小さく触るべき。

### 第二候補: LANL 2015

「実組織の正常行動」を見たいなら強い。

理由:

- 58日
- 認証、プロセス、DNS、NetFlow
- red teamあり
- 12GB圧縮でOpTCより現実的

ただし匿名化が強く、具体的なWindows操作説明は弱い。

### 第三候補: LANL 2017

正常行動ベースライン用。

理由:

- 90日
- Windows host events
- NetFlow
- 長期正常行動

攻撃研究の主軸には弱い。

## 方針案

次にやるべきことは、OpTCを全量取得ではなく、まず構造確認だけすること。

1. OpTCのGroundTruth PDFを読む
2. 修正版OpTCのファイル一覧を確認する
3. 影響ホストと日付を1つ選ぶ
4. その日・そのホストのeCARだけ取得できるか試す
5. プロセス作成、ネットワーク、ファイル操作の関係が復元できるか見る

これができれば、OpTCは主データ候補になる。

できなければ、LANL 2015を主軸にして「実企業正常行動 + red team周辺ログ探索」に寄せる。
