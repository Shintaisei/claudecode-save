# 10単位異常検知 top10 整理と生ログ導線

更新日: 2026-05-19

## 1. 目的

- 次にやるべきこととして、`10` 単位での異常検知結果を先に解釈する
- 特に `top10` の中で、攻撃と正常がどの程度含まれているかを明確にする
- あわせて、実際に異常検知モデルにかけたときの生ログレビューへすぐ入れるようにする

## 2. まず結論

今回見るべき対象は、`LOF` による third pass の `top10 micro-chunk` である。  
各候補は `10 event` 単位なので、`top10` 全体では合計 `100 event` を見ることになる。

その内訳は次の通り。

- `top10 micro-chunk` の本数
  - 攻撃を含む micro-chunk: `5`
  - 完全正常の micro-chunk: `5`
- `100 event` 全体の内訳
  - attack event: `11`
  - normal event: `89`

つまり、**top10 の時点で「完全に攻撃側だけ」でも「完全に正常側だけ」でもなく、攻撃近傍と正常候補が半々で混在している** と読むのが自然である。

## 4. どう解釈するか

### 4.1 攻撃側

攻撃を含むのは `rank 1, 3, 4, 5, 8` の `5本`。  
ここは `payload.exe` が強く出ており、**異常検知が本当に怪しい側を前に出せているか** を確認する帯である。

### 4.2 正常側

完全正常なのは `rank 2, 6, 7, 9, 10` の `5本`。  
ただし `rank 2` は `payload.exe` を含みつつ label 上は `0 / 10` なので、clean な正常 seed というより **攻撃隣接の混合文脈** と見た方がよい。

実務で正常候補として見やすいのは次の `4本`。

- `rank 6`: `chunk204 micro02`
  - `repmgr.exe`
- `rank 7`: `chunk244 micro08`
  - `explorer.exe`
- `rank 9`: `chunk203 micro05`
  - `repmgr.exe`
- `rank 10`: `chunk203 micro07`
  - `winword.exe`

つまり、**top10 の中で本当に正常ユースケース候補として使いやすいのは、完全正常 `5本` のうちさらに `4本` 程度** と読める。
