# ATLAS v2 S3 異常検知フローと抽出結果

更新日: 2026-05-04

## 1. 目的

この段階の目的は、attack day の巨大なログ全体を直接読むのではなく、

1. まず怪しい sequence を少数まで絞る
2. その中で読むべき chunk をさらに絞る
3. 最終的に、正常行動分析へ使える attack-near context を残す

ことである。

## 2. フロー

今回の抽出フローは次の 3 段階である。

### 2.1 First Pass

- ログ: `Security`
- 単位: `computer_user + 10分`
- 学習: benign-only
- モデル: `IsolationForest`
- 特徴: `1-2 gram TF-IDF`

役割は、attack day 全体から suspicious sequence を少数に絞ることである。

### 2.2 Second Pass

- 入力: first-pass 陽性 sequence
- 単位: `100 event chunk`
- 方式: `KNN benign distance + rare process onset + delta onset`

役割は、陽性 sequence の内部をさらに局所化して、読む順番を付けることである。

### 2.3 Sysmon 補助

- ログ: `Sysmon`
- 単位: `1分 bucket`
- 学習: benign-only
- 評価: `Security` のラベルのみ使用

役割は、second pass を置き換えることではなく、minute 単位の補助起点を追加することである。

## 3. First Pass の結果

最も安定していた coarse detector は次である。

- `IsolationForest + Security(computer_user + 10分) + 1-2 gram TF-IDF`
- `F1=0.667, Precision=0.667, Recall=0.667`

S3 では test `18 sequence` のうち `3 sequence` を陽性とした。

- 真陽性: `2`
- 偽陽性: `1`

## 4. Second Pass の結果

First pass 陽性 3 sequence の合計は `118,495 event` であった。

- attack event: `286`
- normal event: `118,209`

ここに second pass を適用すると、review 対象は `10 window / 5,400 event` まで縮んだ。

- attack event: `195`
- normal event: `5,205`

つまり、読む量は `118,495 -> 5,400` で約 `95.4%` 削減である。

## 5. さらに絞った high-confidence seed

実務的に最初に見る起点をさらに減らすため、`payload.exe / powershell.exe / regsvr32.exe` を dominant process に持つ window だけを high-confidence seed として残した。

その結果は次である。

- `6 window / 3,000 event`
- attack event: `195`
- normal event: `2,805`

つまり、review queue からさらに `5,400 -> 3,000` へ絞れている。  
first pass から見ると、`118,495 -> 3,000` で約 `97.5%` 削減である。

## 8. 現時点の読み

今回の抽出は、異常検知そのものを最終目的にしたものではなく、正常行動分析のための絞り込みとして見るべきである。

その観点では、現時点で次まではかなり言いやすい。

- coarse sequence は `3本` まで絞れた
- 実際に読む候補は `10 window` まで絞れた

- しかもその seed の中に大量の正常イベントが残っている

したがって、抽出段階としてはここで一旦完了としてよい。
