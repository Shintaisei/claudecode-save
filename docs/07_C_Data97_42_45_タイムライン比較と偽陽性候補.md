# C_Data/97・42・45 タイムライン比較と偽陽性候補
> 作成日: 2026-04-15  
> 目的: 主対象候補である C_Data/97, C_Data/42, C_Data/45 について、時間帯別の行動とWazuhアラートの重なりを確認し、正常行動復元の対象になりうる偽陽性候補を整理する。

---

## 1. 結論

3ホストを比較すると、主対象は **C_Data/97** が最も扱いやすい。

理由は以下である。

- Wazuhアラートが611件で、初回分析として破綻しにくい
- Securityログが十分にあり、ログオンや権限文脈を追いやすい
- Dropbox、OneDrive、Discord、PDF24、LibreOffice、Zoom、Adobe Acrobat など、日常利用に近いソフトがある
- 実際に `Dropbox.exe`, `OneDrive.exe`, `Discord.exe`, `PDF24` などのユーザー起動・ユーザー初期化らしいプロセスがSysmonに出ている
- それらの時間帯に、Wazuhの `Explorer process was accessed`, `Executable dropped`, `taskschd.dll`, `Discovery` などのアラートが出ている

一方で、C_Data/42 と C_Data/45 は比較・補助として使うのがよい。

| ホスト | 位置づけ | 判断 |
|---|---|---|
| C_Data/97 | 主対象 | 日常利用寄りの行動とWazuhアラートの両方があり、件数も扱いやすい |
| C_Data/42 | 比較対象 | ログ量は多いが、開発・セットアップ・Windows Update寄りの行動が強い |
| C_Data/45 | 補助対象 | Teams/Webex/Zoom系の業務端末らしさはあるが、実際のアラートはChocolatey/.NET/Discord寄り |

---

## 2. 注意: WazuhとSysmonの時刻ずれ

分析中、Wazuhの `@timestamp` と Sysmon の `TimeCreated` が完全には一致しない場面があった。

例として、C_Data/97では Wazuh上の `net.exe` / `SecEdit.exe` 系アラートが `2024-09-16T07:31Z〜07:36Z` に出ている一方、Sysmonの対応プロセスは `2024-09-16 17:36` 頃に見える。

そのため、この文書では以下の方針にする。

- 分単位の完全一致だけで判断しない
- 同一ホスト・同一プロセス・同一コマンドライン・同一フェーズで対応を確認する
- 復元ケース化するときは、起点アラートの前後30分に加えて、必要なら前後90分まで広げる
- 最終ケースでは、Wazuh時刻とSysmon時刻の基準を明記する

## 4. C_Data/97

### 4.1 ホストの性格

C_Data/97 は Windows 11 Home の正常ホストであり、以下のような日常利用寄りソフトが入っている。

- Firefox
- SumatraPDF
- VLC
- PDF24 Creator
- LibreOffice
- Zoom Workplace
- Adobe Acrobat
- Dropbox
- Discord
- OneDrive

ソフト構成だけでなく、Sysmon上でも `Dropbox.exe`, `OneDrive.exe`, `Discord.exe`, `PDF24` などが見えている。

### 4.2 時間帯別タイムライン

| 時間帯 | Sysmonで見えた行動 | Wazuhアラート | 解釈 |
|---|---|---|---|
| 2024-09-06 02:00 | `setx.exe`, `mmc.exe`, `choco.exe`, `regsvr32.exe`, `msedge.exe` | 目立つWazuhなし | 初期設定・環境準備 |
| 2024-09-16 04:00 | `msiexec.exe`, `FileCoAuth.exe`, `regsvr32.exe`, `WinSAT.exe` | 目立つWazuhなし | ソフト導入・Windows/Office系初期化 |
| 2024-09-16 05:00 | `wevtutil.exe`, `choco.exe`, `rundll32.exe`, `powershell.exe` | 目立つWazuhなし | 更新・インストール・イベントログ関連処理 |
| 2024-09-16 06:00 | `Discord.exe`, `Update.exe`, `DiscordSetup.exe`, `reg.exe`, `msiexec.exe` | 目立つWazuhなし | Discord導入・更新処理 |
| 2024-09-16 17:00 | `Dropbox.exe`, `OneDrive.exe`, `Discord.exe`, `PDF24`, `net.exe`, `SecEdit.exe`, `wevtutil.exe` | Windows logon, Discovery, taskschd.dll, Defender LSASS, Explorer access, Executable dropped | ユーザーログオン後のアプリ初期化 + Wazuh監査 |

### 4.3 行動とアラートの重なり

| 行動 | 対応しそうなWazuhアラート | 偽陽性候補としての評価 |
|---|---|---|
| Wazuh agent による `net.exe accounts`, `net user administrator`, `SecEdit.exe /export` | `Discovery activity executed`, `A net.exe account discovery command was initiated`, `SecEdit.exe binary in a suspicious location` | 高い。攻撃のDiscoveryに見えるが、親プロセスが `wazuh-agent.exe` |
| Dropbox起動・更新 | `Executable dropped in Windows root folder` | 高い。`DropboxUpdate.exe` が `C:\Windows\Temp\GURC786.exe` を作成しており、アラート名だけ見ると怪しい |
| OneDrive起動 | `Explorer process was accessed by OneDrive.exe, possible process injection` | 高い。OneDriveの通常起動・Explorer連携が、プロセスアクセス系アラートになっている |
| Discord起動 | 関連アラートは限定的。C_Data/45ではDiscord由来のExplorer accessが多い | 中。C_Data/97では行動は見えるが、主アラートとしてはやや弱い |
| PDF24起動 | 直接対応する強いWazuhアラートは未確認 | 低〜中。日常行動としては良いが、起点アラートとしては弱い |
| Defender更新・LSASS参照 | `Lsass process was accessed by MsMpEng.exe ... possible credential dump` | 高い。正常なDefender動作を攻撃っぽく検知している |

### 4.4 C_Data/97で優先する復元ケース

| 優先度 | ケース | 理由 |
|---:|---|---|
| 1 | Dropbox Update が `C:\Windows\Temp` にEXEを作成 | 日常系アプリ更新が「Executable dropped」として出ており、偽陽性説明に向く |
| 2 | OneDrive が Explorer にアクセス | OneDrive/Explorer連携が「possible process injection」として出ており、正常説明しやすい |
| 3 | Wazuh監査による `net.exe` / `SecEdit.exe` | 攻撃っぽいDiscoveryだが、親プロセスから正常監査と説明できる |
| 4 | DefenderのLSASSアクセス | セキュリティ製品の正常動作が credential dump 風に見える |

C_Data/97 は、C_Data/96よりも日常アプリ由来の偽陽性候補がある。  
したがって主対象として妥当である。

## 5. C_Data/42

### 5.1 ホストの性格

C_Data/42 は Windows 11 Home の正常ホストで、Docker Desktop、Git、Python、Node.js、GIMP、Firefox、VLC、Notepad++ などが入っている。

日常業務というより、開発者・技術者寄り端末として扱うのが自然である。

### 5.2 時間帯別タイムライン

| 時間帯 | Sysmonで見えた行動 | Wazuhアラート | 解釈 |
|---|---|---|---|
| 2024-09-06 02:00 | `setx.exe`, `mmc.exe`, `choco.exe`, `regsvr32.exe` | 目立つWazuhなし | 初期設定 |
| 2024-09-11 00:00 | Sysmonプロセス作成は少ない | Discovery, logon, scripting file, taskschd.dll が多数 | Wazuh/Security側で監査イベントが集中 |
| 2024-09-11 01:00 | `wevtutil.exe`, `net.exe`, `net1.exe`, `choco.exe`, `msiexec.exe`, `git.exe`, `kubectl.exe` | Executable dropped, logon, taskschd.dll, Discovery | 開発環境構築 + Wazuh監査 + Windows更新 |
| 2024-09-11 02:00 | `wevtutil.exe`, `net.exe`, `net1.exe`, `sdbinst.exe` | taskschd.dll, logon, Application Compatibility Database | 更新・互換性DB・監査 |
| 2024-09-11 03:00 | `sdbinst.exe` | logon, taskschd.dll, Discovery, Defender LSASS | システム処理中心 |
| 2024-09-11 04:00 | `wevtutil.exe`, `net.exe`, `net1.exe`, `powershell.exe`, `FileCoAuth.exe` | 目立つWazuhなし | 後処理・ログ収集 |

### 5.3 行動とアラートの重なり

| 行動 | 対応しそうなWazuhアラート | 偽陽性候補としての評価 |
|---|---|---|
| Wazuh監査による `net.exe` / `net1.exe` | `Discovery activity executed`, `A net.exe account discovery command was initiated` | 高い。ただしC_Data/97/96でも同型ケースがある |
| Windows Update / SoftwareDistribution配下のDLL作成 | `Possible DLL search order hijack ... SoftwareDistribution ...` | 高い。正常更新がDLLハイジャック風に見える |
| PowerShellによる一時スクリプト作成 | `Scripting file created`, `Powershell process created an executable file` | 中〜高。親子関係の確認が必要 |
| Git / kubectl / Docker系 | 直接対応するアラートは未確定 | 中。開発者端末らしいが、起点アラートとしてはまだ弱い |

### 5.4 C_Data/42の使いどころ

C_Data/42 は、開発者端末・Windows Update系の正常行動復元に向いている。

ただし、初回の主対象としてはC_Data/97よりやや重い。  
理由は、セットアップ・開発環境構築・Windows Update・Wazuh監査が混ざり、行動単位の切り分けが難しいためである。

### 6.1 ホストの性格

C_Data/45 は Windows 11 Home の正常ホストで、TeamViewer、Webex、Zoom、Firefox、Notepad++、Edge、Wazuh Agent が入っている。

ソフト構成としては、3ホストの中で最も業務端末らしい。

### 6.2 時間帯別タイムライン

| 時間帯 | Sysmonで見えた行動 | Wazuhアラート | 解釈 |
|---|---|---|---|
| 2024-09-06 02:00 | `setx.exe`, `mmc.exe`, `choco.exe`, `regsvr32.exe` | 目立つWazuhなし | 初期設定 |
| 2024-09-11 19:00 | `choco.exe`, `msiexec.exe`, `WerFault.exe`, `Discord.exe`, `Teams.exe`, `Update.exe`, `regsvr32.exe`, `icacls.exe` | PowerShell automation library, Executable dropped, logon, taskschd.dll, Discovery | ソフト導入・Teams/Discord系初期化 |
| 2024-09-11 20:00 | `wevtutil.exe`, `net.exe`, `net1.exe`, `Discord.exe`, `OneDrive.exe`, `SecEdit.exe`, Defender関連 | 目立つWazuhなし、または時刻ずれの可能性 | Wazuh監査 + Discord/OneDrive起動 + Defender後処理 |

### 6.3 行動とアラートの重なり

| 行動 | 対応しそうなWazuhアラート | 偽陽性候補としての評価 |
|---|---|---|
| Chocolateyによる導入 | `Binary loaded PowerShell automation library`, `Executable dropped in Windows root folder` | 高い。ただしセットアップ系 |
| .NET Native Image / `mscorsvw.exe` | `Executable dropped`, `PowerShell automation library` | 高い。正常な.NET最適化処理が怪しく見える |
| Discord起動 | `Explorer process was accessed by Discord.exe, possible process injection` | 高い。ユーザーアプリ由来の偽陽性として使いやすい |

### 6.4 C_Data/45の使いどころ

C_Data/45 は、業務ソフトが入っている点では魅力がある。  
ただし、実際に強く出ているWazuhアラートは Chocolatey、.NET、Discord、Wazuh監査寄りである。

そのため、主対象というより、**Discord/Teams/Webex/Zoom系の業務端末らしさを補助的に示すホスト** として使うのがよい。

## 8. 主対象の判断

主対象は **C_Data/97** とする。

理由:

1. C_Data/96よりセットアップ・監査偏りが弱い。
2. C_Data/42よりWazuh件数が少なく、初回分析に向く。
3. C_Data/45よりSecurity/Sysmon/アラートのバランスが良い。
4. Dropbox、OneDrive、Discordなど、日常利用アプリ由来の偽陽性候補がある。
5. Wazuh監査、Defender、Dropbox、OneDriveという複数タイプの正常行動を比較できる。

したがって、次に作るべき資料は以下である。

1. `C_Data97_ホスト行動タイムライン整理.md`
2. `C_Data97_正常行動_起点アラート分類.md`
3. `C_Data97_CASE_001_DropboxUpdate.md`

## 9. 次に取得するべき情報

最初のケースとして、C_Data/97 の Dropbox Update を扱う。

対象:

- `DropboxUpdate.exe`
- `C:\Windows\Temp\GURC786.exe`
- `Executable dropped in Windows root folder`

取得するログ:

| ログ | 見る内容 |
|---|---|
| Sysmon EID 1 | Dropbox/DropboxUpdateの親子関係 |
| Sysmon EID 11 | `C:\Windows\Temp\GURC786.exe` の作成 |
| Wazuhアラート | `Executable dropped in Windows root folder` の詳細 |
| Securityログ | 同時刻のログオンユーザー、必要なら補助 |

目的:

> 攻撃っぽい「Windows TempへのEXE作成」が、Dropboxの正常更新処理として説明できるかを検証する。
