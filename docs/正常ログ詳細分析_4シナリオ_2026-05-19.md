## 1. まず全シナリオに共通する特徴

### 1-1. EventID は ProcessCreate / ProcessTerminate の2種類しかない

```
全4シナリオ共通:
  EventID 1: ProcessCreate    (プロセス起動)
  EventID 5: ProcessTerminate (プロセス終了)

  それ以外のSysmonイベントは含まれない:
  × EID 3  NetworkConnect
  × EID 7  ImageLoad
  × EID 11 FileCreate
  × EID 12 RegistryCreate
  × EID 22 DnsQuery
```

**意味:** この 100 ログは「何かが起動した・終了した」という記録のみ。  
ファイルに何を書いたか・どこに通信したか・何のDLLを読んだか、は含まれない。

### 1-2. `repwmiutils.exe` が全シナリオで最多プロセス

```
repwmiutils.exe の件数:
  M4: 22/96件 (23%)
  M6: 36/97件 (37%)
  S4: 34/91件 (37%)
  S3: 33/95件 (35%)
```

CommandLine: `RepWmiUtils.exe muuid`（一定の引数で繰り返し起動・終了するだけ）  
→ WMI 管理ユーティリティの定期呼び出し。意味のある業務操作ではなくバックグラウンド処理。  
→ **4 シナリオすべての正常ログの中核は、この反復起動が占めている。**

### 1-3. 共通して現れる背景プロセス群

```
全シナリオ共通:
  dllhost.exe          COM サロゲートプロセス（COM オブジェクト呼び出し時に生成される）
  conhost.exe          コンソールホスト（cmd.exe など CUI プロセスの描画担当）
  dumpcap.exe          Wireshark のパケットキャプチャ実行プロセス
  firefox.exe          Firefox ブラウザの起動・終了
  flashplayerupdateservice.exe  Flash Player 自動更新サービス
```

## 4. 発表で使える解釈

### 正常ログの本体は何か

```
この 100 ログは主に以下の3層から構成される:

  層1（核）:  repwmiutils.exe の定期起動・終了（全件の 23〜37%）
              → 業務的意味はなく、OSレベルの定期処理

  層2（文脈）: dllhost, conhost, cmd, dumpcap 等の起動・終了
              → ユーザー操作または他プロセス呼び出しに付随する OS 基盤処理

  層3（主役）: excel, winword, mmc, upd 等（シナリオによって存在/不在が変わる）
              → 実際の業務行動や更新処理を表す候補
              → M6 が最も説明しやすい（Word 文書操作の文脈が明確）
```

### M6 が最も説明力が高い理由

```
M6 の attack_near minute（T0009Z）の構造:

  eqnedt32.exe  ← Word の数式エディタ（攻撃に悪用）
  regsvr32.exe  ← DLL 登録ツール（悪意のある DLL を登録）
  winword.exe   ← Word 本体（正常な文書閲覧処理として起動中）
  dllhost.exe   ← COM サロゲート（Word の COM 呼び出しに付随）
  werfault.exe  ← クラッシュ検出（攻撃後のクラッシュに反応）

  → 「Word で文書を開いた」という正常行動の痕跡が、
    攻撃プロセスと完全に同一 minute に混在している
  → アナリストが「これは攻撃か正常か」と迷う最も典型的なシーン
```
