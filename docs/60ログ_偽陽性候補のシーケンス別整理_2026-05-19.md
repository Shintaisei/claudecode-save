# 60ログ 偽陽性候補のシーケンス別整理

作成日: 2026-05-19

## 1. この60ログの定義

ここでいう `60ログ` は、`top10 micro-chunk` の `100 event` のうち、

- `attack label = 0`
- `process != payload.exe`

を満たす event を抜いたものを指す。

つまり今回は、

- `attack label = 1` の event: `11`
- `attack label = 0 かつ process = payload.exe` の event: `29`
- `attack label = 0 かつ process != payload.exe` の event: `60`

という3分割のうち、最後の `60 event` を偽陽性候補として見る。

## 2. 全体像

まず明確になったのは、`60ログ` は広く散らばった多様な候補群というより、
**ほぼ `tpautoconnect.exe` の file access 反復を中心にしつつ、一部に `repmgr.exe`, `explorer.exe`, `winword.exe`, `csrss.exe` が混じる構造** だという点である。

そのため、実務上の読み方としては次の2段階が自然である。

1. `60ログ` 全体を「偽陽性候補の母集団」として扱う
2. その中で、説明しやすい sequence を正常ユースケース候補として優先する

## 4. sequence ごとの中身

### seq 1

- 件数: `4`
- 中身:
  - `csrss.exe 4658`
  - `tpautoconnect.exe 4656`
  - `tpautoconnect.exe 4663`
  - `tpautoconnect.exe 4658`
- 解釈:
  - `payload.exe` を含む attack 近傍に混ざった背景反復の一部
  - 単独の正常ユースケースというより、attack 周辺ノイズとして読む方が自然

### seq 2

- 件数: `7`
- 中身:
  - `tpautoconnect.exe` の `4656 / 4663 / 4658` 反復が `6件`
  - `csrss.exe 4656` が `1件`
- 解釈:
  - `attack label` は付いていないが、同一 sequence 内に `payload.exe` が混在している
  - そのため clean normal ではなく、`payload.exe` 近傍で出た normal 側 event として扱うのが安全

### seq 3

- 件数: `2`
- 中身:
  - `tpautoconnect.exe 4656`
  - `tpautoconnect.exe 4663`
- 解釈:
  - attack 近傍 sequence の末端に残った normal 側
  - ユースケース候補というより補助的な background event

### seq 4

- 件数: `1`
- 中身:
  - `tpautoconnect.exe 4656`
- 解釈:
  - 単発で文脈が薄く、独立した正常ユースケースにはしにくい

### seq 5

- 件数: `1`
- 中身:
  - `tpautoconnect.exe 4656`
- 解釈:
  - seq 4 と同じく、attack 近傍に付随した単発背景 event

### seq 6

- 件数: `10`
- 中身:
  - `tpautoconnect.exe` が `6件`
  - `repmgr.exe` が `4件`
- 主な並び:
  - `tpautoconnect.exe 4663 -> 4658 -> 4656 -> 4663 -> 4658`
  - `repmgr.exe 4663 -> 4656 -> 4663 -> 4658`
- 解釈:
  - 文書関連オブジェクトに対するアクセス連鎖として読みやすい
  - 既存整理でも `repmgr.exe` 帯は文書関連アクセスの局所まとまりとして扱われており、正常手続候補として説明しやすい

### seq 7

- 件数: `10`
- 中身:
  - `tpautoconnect.exe` が `7件`
  - `explorer.exe` が `3件`
- 主な並び:
  - 前半は `tpautoconnect.exe` の `4658 / 4656 / 4663` 反復
  - 後半に `explorer.exe 4656 -> 4663 -> 4656`
- 解釈:
  - ユーザのファイル参照や画面操作に近い局所まとまり
  - `explorer.exe` が見えているため、単発操作型の正常候補として説明力が高い

### seq 8

- 件数: `5`
- 中身:
  - `tpautoconnect.exe 4663`
  - `tpautoconnect.exe 4658`
  - `tpautoconnect.exe 4656`
  - `tpautoconnect.exe 4663`
  - `tpautoconnect.exe 4658`
- 解釈:
  - `payload.exe` を含む sequence の中で切り出された normal 側
  - attack 近傍の normal event としては使えるが、独立正常としては弱い

### seq 9

- 件数: `10`
- 中身:
  - `tpautoconnect.exe` が `9件`
  - `repmgr.exe 4656` が `1件`
- 主な並び:
  - `tpautoconnect.exe` の `4656 -> 4663 -> 4658` 反復
  - 末尾に `repmgr.exe 4656`
- 解釈:
  - seq 6 より `repmgr.exe` の見え方は弱いが、文書関連手続へつながる背景として使える
  - 単独で強いより、seq 6 とセットで「文書関連アクセス帯」として扱うのが自然

### seq 10

- 件数: `10`
- 中身:
  - `winword.exe 4658` が `1件`
  - `tpautoconnect.exe` が `9件`
- 主な並び:
  - 冒頭に `winword.exe`
  - その後 `tpautoconnect.exe` の `4656 -> 4663 -> 4658` 反復
- 解釈:
  - 文書閲覧・文書操作帯として説明しやすい
  - `winword.exe` が見えるため、発表で「何の正常行動か」を伝えやすい candidate

## 5. 60ログの再分類

この `60ログ` は、説明上は次の3群に分けると分かりやすい。

### A. attack 近傍の normal 側

- `seq 1, 2, 3, 4, 5, 8`
- 合計 `20ログ`
- 特徴:
  - `payload.exe` を含む高異常スコア sequence の中で、`attack label` が付いていない event
  - 背景ノイズまたは前後処理として現れている

### B. 文書・ファイル操作として比較的説明しやすい群

- `seq 6, 7, 9, 10`
- 合計 `40ログ`
- 特徴:
  - `repmgr.exe`, `explorer.exe`, `winword.exe` が見える
  - `top10` の中でも、正常ユースケース候補として最も説明しやすい

### C. 背景反復の核

- 全 sequence に広く存在する `tpautoconnect.exe`
- 特徴:
  - `4656 / 4663 / 4658` の反復が中心
  - これ自体は background noise として切り分ける方がよい
  - ただし、他プロセスが混ざることで sequence の意味が立ち上がる

## 6. 現時点での結論

- `60ログ` は「使えそうな偽陽性候補の母集団」としては成立する
- ただし、その中身の大半は `tpautoconnect.exe` 反復であり、**そのまま全部を独立ユースケース化するのは難しい**
- 実際に説明力が高いのは、`seq 6, 7, 9, 10` を中心とする `40ログ`
- 特に発表で扱いやすいのは次の3系統
  - `repmgr.exe` を含む文書関連アクセス
  - `explorer.exe` を含むファイル参照
  - `winword.exe` を含む文書閲覧

## 7. 次にやるべきこと

1. `seq 6, 7, 9, 10` を優先して、各 sequence の対象ファイルや前後帯を追加確認する
2. `tpautoconnect.exe` は背景反復として整理し、主体ユースケース候補からは一段下げて扱う
3. 発表では `60ログ全部が有力` ではなく、`60ログを洗った結果、説明力が高い正常候補は文書・ファイル操作帯に集中した` と言うのが安全
