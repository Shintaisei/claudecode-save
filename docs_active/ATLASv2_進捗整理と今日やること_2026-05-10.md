# ATLASv2 進捗整理と今日やること
更新日: 2026-05-10

## 1. 研究の今の位置づけ

- 目的は、異常検知後のログを対象に
  - 関連ログの調達
  - 行動の復元
  - 攻撃 / 正常 / 決めきれないの判断
  を自動化すること
- 現在はその第一段階として、**正常行動でも探索が成立するか** を検証するためのユースケース作成を進めている
- そのために、オープンソースデータセット `ATLAS / ATLAS v2` から、**異常検知で怪しく見える正常行動** を抽出している

## 2. ここまでの進捗

### 2.1 個別ログ検知からシーケンス検知へ方針転換した

- `Hayabusa` による個別ログ検知では、攻撃をほとんど拾えず、今回ほしい
  - 攻撃近傍の正常行動
  - 追跡の起点になりそうな正常ログ
  を十分に回収できなかった
- そのため、単一ログではなく前後文脈を扱える**シーケンス単位の異常検知**へ移行した

### 2.2 first pass は主結果として成立した

- 採用構成:
  - `ユーザ単位・10分ごと`
  - `1-2gram TF-IDF`
  - `IsolationForest`
  - benign validation 由来の `p95` 閾値
- `S3 attack day` では
  - `257,887 log`
  - `18 sequence`
  を
  - `118,495 log`
  - `3 sequence`
  まで絞れた
- 指標としても `F1=0.667, Recall=0.667, Precision=0.667` で、今回の目的に対して最も安定していた

### 2.3 second pass で読む範囲をさらに局所化できた

- first pass 後の `118,495 log` を `100 event chunk` に分け、rule-free に比較した
- 比較対象:
  - `LOF`
  - `OneClassSVM`
  - `IsolationForest`
  - `kNN distance`
  - `SGDOneClassSVM`
  - `SVD reconstruction error`
- 結果として
  - `LOF` は `first attack rank = 1`
  - `OneClassSVM` は `first attack rank = 2`
  - `SVD` も attack には届く
  という形で、chunk 単位の再順位付けは成立した
- 安全側では `top10 chunk = 1,000 event` まで圧縮でき、起点抽出だけなら `100〜300 event` まで詰められる可能性がある

## 3. 5/8 時点の発表整理

5/8 の資料では、今の進捗を次の流れで説明している。

1. 実務では偽陽性解析が多いのに、先行研究は攻撃前提の分析が中心
2. そのギャップに対して、まず正常行動側で探索が成立するかを検証する
3. 個別ログ検知では難しかったため、シーケンス検知へ移行した
4. first pass で 25 万件規模から約 11 万件まで絞れた
5. second pass で 100〜1000 件規模までさらに読む範囲を集約できた
6. 次は、その上位 chunk から研究対象にする正常行動ユースケースを抜き出す

## 4. いまの結論

- 主結果は first pass
  - `ユーザ単位・10分ごと + 1-2gram TF-IDF + IsolationForest`
- second pass は補助結果
  - `LOF` は早く attack に届く
  - `OneClassSVM` はやや保守的に絞る
  - `SVD` は補助候補
- second pass の出力は、完全な行動再構成そのものというより、**追跡の起点候補抽出**に向いている

## 5. 今日やること

今日の主タスクは、second pass で絞った上位 chunk から、**研究で使う正常行動ユースケース候補を確定すること**。

優先順は次の通り。

1. `LOF top10` を中心に、pure normal かつ意味づけしやすい chunk を確定する
2. `winword.exe` / `repmgr.exe` / `explorer.exe` / `firefox.exe` を含む候補を、文書操作・ファイル操作・ブラウザ操作として整理する
3. `tpautoconnect.exe` 中心の background noise はユースケース候補から切り分ける
4. 必要なら `OneClassSVM` 上位 chunk も見て、LOF 偏重になっていないか確認する
