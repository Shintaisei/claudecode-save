# LOF 小集合ログの9マス分析

更新日: 2026-05-10

## 1. 目的

- `top100` 全体から後で都合よく拾ったように見えないように、異常検知で自然に上位化された小集合だけを対象にする
- その小集合から、後続の関連ログ調達ユースケースをどの9マスに置けるかを整理する
- 今回は「正常行動関連のログが 1 つでも異常検知で引っかかっていれば採択可」という基準で見る

## 2. 今回の対象集合

- second pass: `LOF top10 chunk`
- 対象 event 数: `1,000`
- third pass: 各 `100 event chunk` を `10 event micro-chunk` に再分割
- 再ランキング: `LOF`
- 実務でまず見る小集合:
  - attack 近傍の上位 `4 micro-chunk`
  - normal seed として説明しやすい上位 `4 micro-chunk`

## 4. 9マスの軸

- 横軸: 正常行動種別
  - `単発操作型`: `explorer.exe`, `winword.exe`, `firefox.exe` など、単独でも意味が取りやすい操作
  - `手続型`: `repmgr.exe -> winword.exe` のように、複数操作の連鎖として読む方が自然なもの
  - `背景動作型`: `tpautoconnect.exe`, `spoolsv.exe`, `tpautoconnsvc.exe` のように、背景反復が中心のもの
- 縦軸: 起点アラート特異性
  - `高`: LOF third pass の上位 `10` に入り、かつ人が説明しやすい正常関連プロセスが見える
  - `中`: LOF 上位には入るが、背景ログが強く、周辺参照がないと意味づけしにくい
  - `低`: broad noise に近く、今回の小集合だけでは起点として弱い

| `低` | `今回は採らない` | `今回は採らない` | `今回は採らない` |

## 6. どのマスが今すぐ埋まるか

- `高 x 単発操作型`
  - `chunk244 micro08`
  - `chunk203 micro07`
  - `explorer.exe` と `winword.exe` が単独でも意味を持つ
  - しかも LOF micro rank `7`, `10` で異常検知に引っかかっている

- `高 x 手続型`
  - `chunk204 micro02`
  - `chunk203 micro05`
  - `repmgr.exe` 単体よりも、文書アクセス連鎖の一部として使う方が自然
  - これも LOF micro rank `6`, `9` で異常検知に引っかかっている

## 7. 今回はまだ弱いマス

- `高 x 背景動作型`
  - `top10 chunk -> micro10` の LOF 上位では、背景型は `tpautoconnect.exe` の反復が強すぎる
  - 異常には見えるが、関連ログ調達ユースケースとしては説明が弱い

- `中` 以下の各マス
  - 今回の方針は「実務者が自然に上から見る小集合」を優先するため、意図的に広げて埋めには行かない
  - browser 系は `rank 43-47` 側を third pass すれば `中 x 単発操作型` の候補になりやすい
  - `spoolsv.exe` / `tpautoconnsvc.exe` 群を別扱いすれば `中 x 背景動作型` の候補は作れる

## 8. 実務向けの解釈

- 今回の小集合だけでも、9マスのうち
  - `高 x 単発操作型`
  - `高 x 手続型`
  の 2 マスはかなり自然に埋められる
- 重要なのは、どちらも `top10000` から恣意的に拾ったのではなく、
  - second pass の `LOF top10 chunk`
  - third pass の `LOF top10 micro-chunk`
  という順で自然に上位化されたログから出ていること
- 研究上は「正常行動関連のログが 1 つでも異常検知で引っかかればよい」という基準に照らして、今回の 4 micro-chunk は十分採択可能
