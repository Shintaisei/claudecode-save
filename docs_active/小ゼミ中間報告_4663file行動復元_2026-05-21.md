# 小ゼミ中間報告：4663/file を起点としたファイルアクセス行動復元

作成日: 2026-05-21

## 1. 研究目的

本研究の目的は、インシデント分析自動化支援に向けて、異常検知で抽出された高スコアログシーケンスから、調査対象となる行動を復元することである。

今回は Windows Security Log の `Event ID 4663 / ObjectType=file` を中心に、ファイルアクセス行動の復元を対象とする。

本研究で重視する点は、`4663/file` を単なる攻撃判定ログとして扱うのではなく、調査起点となる Point of Interest として再解釈することである。これにより、高スコアシーケンス内に残存する `4663/file` を、正常文脈と攻撃文脈を区別可能な行動単位へ変換することを目指す。

---

## 2. 異常検知による絞り込み

入力データには **ATLAS v2**（ATT&CK Evaluations Labs Adversary Simulation）データセットの Windows Security Event ログを用いた。ATLAS v2 は実際の攻撃シナリオを模擬した環境で収集されたログセットであり、今回は攻撃が実施されたホスト `win-32-h1` の5日目ログを対象とした。対象シナリオは S3・M4・M6・S4 の4つで、いずれも同一ホスト上で異なる時間帯に実行された攻撃を含む。

各シナリオの5日目ログは数万件規模であり、人手での全件確認は不可能である。そのため **IsolationForest → IsolationForest → kNN** の3段階異常スコアリングを適用し、最終的に人が確認可能な規模まで絞り込んだ。

```
【第1段階】10分セッション単位で IsolationForest
  全ログ（数万件）→ 上位30セッション × 100ログ = 約3,000ログ

【第2段階】100ログチャンク単位で IsolationForest
  3,000ログ → 上位30チャンク × 100ログ = 約3,000ログ（再スコアリング）

【第3段階】10ログマイクロチャンク単位で kNN
  3,000ログ → 上位10マイクロチャンク × 10ログ = 100ログ
```

この3段階フィルタリングを S3・M4・M6・S4 の4シナリオに独立して適用した。

| | S3 | M4 | M6 | S4 |
|---|---|---|---|---|
| **時間帯（UTC）** | 07/19 14:20〜14:30 | 07/19 22:30〜23:00 | 07/19 23:50〜07/20 00:00 | 07/20 00:40〜00:50 |
| **残存ログ数** | 100件 / 5 chunk | 100件 / 9 chunk | 100件 / 10 chunk | 100件 / 7 chunk |
| **攻撃ラベル** | 0件 | 1件 | 0件 | 1件 |

4シナリオ合計 **400ログ** を以降の分析対象とする。

## 4. ファイルアクセス系ログを主対象にする理由

インシデント分析では、ログ種別ごとに調査起点としての役割が異なる。

| 起点ログ種別 | 代表 Event ID | 明確にすること | 調査上の役割 |
| --- | --- | --- | --- |
| ログオン系 | 4624, 4625, 4648 | 誰がログオンしたか | 侵入主体・認証異常の把握 |
| プロセス作成系 | 4688 | 何が実行されたか | 攻撃手順・実行行動の把握 |
| 権限使用系 | 4672, 4673 | 高権限操作があったか | 権限昇格・管理操作の把握 |
| サービス/タスク系 | 4697, 4698 | 常駐化・自動実行があったか | 永続化の把握 |
| ログ削除/監査変更系 | 1102, 4719 | 痕跡削除があったか | 隠蔽・証拠削除の把握 |
| ファイルアクセス系 | 4663 | 何にアクセスしたか | 影響範囲・行動結果の把握 |

ログオン系やプロセス作成系は、侵入主体や実行手順を把握するために重要である。一方で、ファイルアクセス系ログは、実行された処理の結果として、どのプロセスがどのファイルにアクセスしたかを示す。

そのため、ファイルアクセスログは攻撃を単体で確定するログではないが、以下の点で実務上の調査起点として有効である。

| 観点 | ファイルアクセスログの価値 |
| --- | --- |
| 影響範囲 | どのファイルにアクセスが及んだかを確認できる |
| 行動結果 | 実行された処理が何に影響したかを確認できる |
| 情報漏えい調査 | 読み取られた可能性のあるファイルを調査できる |
| ランサムウェア調査 | 大量の書き込み・変更・削除の起点になりうる |
| 偽陽性分析 | 正常な管理処理やサービス処理が異常に見える理由を説明できる |

特にファイルアクセスは、攻撃だけでなく、管理エージェント、検索インデックス、印刷スプーラ、監視処理などの正常処理でも大量に発生する。したがって、ファイルアクセスログは調査価値が高い一方で、正常と異常の判断が難しいログでもある。

本研究ではこの点に着目し、`4663 / ObjectType=file` を調査起点ログとして扱う。

---

## 5. 本研究で明確にする行動

本研究では、ファイルアクセスログから攻撃手順全体を復元するのではなく、ファイルアクセスに関する行動単位を復元する。

`4663/file` から直接得られる情報は以下である。

| 要素 | 内容 |
| --- | --- |
| 主体 | ファイルにアクセスしたプロセス |
| 対象 | file object |
| 操作 | オブジェクトアクセス |
| 文脈 | normal / attack_context |
| 行動候補 | 管理処理、検索処理、印刷処理、攻撃文脈内アクセスなど |

したがって、本研究で復元する行動は次のように定義する。

> どのプロセスが、どの文脈で、ファイルアクセスを行ったか

ここでいう攻撃文脈とは、攻撃プロセスそのものを断定することではなく、攻撃ラベル付きシーケンス内で観測されたファイルアクセス行動を指す。

---

## 6. CLOUSEAU との接続

CLOUSEAU は、調査起点である Point of Interest から周辺ログを問い合わせ、関連イベントを集めながら攻撃ナラティブを構成する手法である。

本研究では、この POI 起点調査の考え方をファイルアクセスログに適用する。

```text
4663/file の高スコアログ
↓
調査起点 POI として扱う
↓
周辺ログ・同一 micro・同一プロセスを確認
↓
主体・文脈・行動ラベルを復元
```

すなわち、`4663/file` を単体で判断するのではなく、CLOUSEAU に基づいて周辺文脈を補完し、ファイルアクセス行動として意味づける。

## 8. 出力定義

### 設計方針：POI ベースの行動記述

本研究の出力フォーマットは、インシデント分析の実務フレームワークである **CLOUSEAU**（ACSAC 2025）が採用する **POI（Point of Interest）** 概念を参考に設計する。

CLOUSEAU では、検知アラートの起点となるログ（POI）を中心に関連ログを収集し、「何が・何に・どう作用したか」を構造化して記述する。本研究ではこの考え方をファイルアクセス行動の正常事例に適用し、`4663/file` ログを POI として周辺コンテキストとともに行動を復元する。

出力は単なる `normal / attack` の二値判定ではなく、**誰が・何に・どのような操作をしたか**を説明可能な形で記述することを目指す。これにより、実務のインシデント分析者が「このアラートは正常行動である」と判断する際の根拠情報として活用できる形式とする。

### 出力スキーマ

| 出力項目 | 内容 |
| --- | --- |
| `poi_event` | 起点ログ（POI）。`EventID=4663 / ObjectType=file` |
| `actor` | アクセス主体となるプロセス名 |
| `actor_type` | 主体の種別（管理エージェント・検索インデックス・印刷スプーラ等） |
| `object_type` | `file`（本研究では固定） |
| `access_behavior` | ファイルアクセス行動のラベル（例: `management_agent_file_access`） |
| `context_label` | `normal` / `attack_context`（攻撃ラベル付きchunk内に混在する場合） |
| `related_events` | 同一chunk内の共起イベント（EventID・プロセス・時間帯） |
| `behavior_summary` | 人間向けの行動説明（自然言語） |
| `limitation` | `4663` 単体では断定できない範囲（ObjectName・CommandLine 不在の場合等） |
| `confidence` | 復元確信度（`high` / `medium-high` / `low`） |

## 10. 現時点の主張

本研究では、`4663 / ObjectType=file` を攻撃確定ログではなく、調査起点ログとして扱う。

ファイルアクセスログは、インシデント分析においてアクセス対象、影響範囲、行動結果を明確にするうえで重要である。一方で、正常な管理処理やサービス処理でも大量に発生するため、実務上も正常と異常の判断が難しい。

そこで、CLOUSEAU の POI 起点調査を用いて周辺ログを関連づけ、正常文脈および攻撃文脈におけるファイルアクセス行動を復元する。

## 12. 中間報告としての要点

現時点での中間報告としての中心メッセージは次の 3 点である。

1. `4663/file` は攻撃確定ログではなく、調査起点ログとして扱う。
2. 高スコアシーケンスに残るファイルアクセスログを、周辺文脈と関連づけて行動単位へ変換する。
3. 正常文脈と攻撃文脈の双方を対象に、ファイルアクセス行動復元の可能性を評価する。
