# 偽陽性重視の9マスユースケース完成版

更新日: 2026-05-10

## 1. 目的

- `10 sequence` の異常検知結果を土台に、偽陽性になりやすい正常行動ユースケースを拡張した
- 候補化はすべて `sequence rank` と `micro rank` を付けて行った
- 9マスを機械的に全部埋めるのではなく、**異常検知で本当に上がりやすい正常行動** を優先した

## 2. 今回使った帯域

- `top10 core`
  - 既存の `LOF top10 chunk -> top10 micro-chunk`
  - `explorer.exe / winword.exe / repmgr.exe`
- `browser band`
  - second pass `rank 42-47`
  - third pass で `60 micro-chunk`
- `background band`
  - second pass `rank 74-100`
  - third pass で `270 micro-chunk`

## 3. 重要な観察

- `top10 core` は最も説明しやすい偽陽性候補が集まる
- `browser band` は期待通り `firefox.exe` を含むが、LOF 上位の大半は `tpautoconnect.exe` ノイズで、`firefox.exe` が最初に現れるのはかなり後ろ
- `background band` は `spoolsv.exe` と `tpautoconnsvc.exe` が非常に早い順位で出る
- `repwmiutils.exe` は background 帯の中で比較的早く現れる非core候補で、手続型寄りの偽陽性ケースとして使いやすい

## 6. 研究としての解釈

- `explorer.exe / winword.exe / repmgr.exe`
  - もっとも自然にユースケース化できる
  - しかも異常検知でかなり前に出ている

- `firefox.exe`
  - 重要な候補ではあるが、`browser band` の中では前に出にくい
  - これは「browser 系正常行動はノイズに埋もれやすい」という知見として使える

- `spoolsv.exe / tpautoconnsvc.exe`
  - 上位には出るが、追跡ユースケースとしては難しい
  - `偽陽性にはなりやすいが追跡困難` の代表例として使いやすい

- `repwmiutils.exe`
  - 背景帯の中でも比較的扱いやすく、`手続型と背景動作型の中間` のような位置づけ

## 7. CLOUSEAU に渡す順番

`CLOUSEAU` の実験は次の順でやるのが自然。

1. `explorer.exe`
2. `winword.exe`
3. `repmgr.exe`
4. `firefox.exe`
5. `repwmiutils.exe`
6. `spoolsv.exe`
7. `tpautoconnsvc.exe`

前半 3 つで「追跡しやすい偽陽性」、後半 4 つで「追跡しにくい偽陽性」を見られる。

## 9. まとめ

- 9マスは、偽陽性重視でも `6-7` 候補まで自然に拡張できた
- しかもすべて `sequence rank + micro rank` 付きで候補化できている
- 実験としては、

    を追跡しやすい群

    を追跡しにくい群
  として扱うのが最もきれい
